## 1. 为什么单独有这份「共享契约」

用户的目标是 **React 核心 + Web/Desktop（Tauri 2）+ Mobile（React Native）** 多端生态。
多端意味着：**有 N 个端，就有 N 份可能漂移的实现。**

**⇒ 本文件定义「所有端必须一致的东西」**，各端的施工方案只写「本端怎么实现」，**不重复定义契约**（D4）。

**判据**：任何"两个端各写一遍"的东西，都应该在这里有唯一定义。

---

## 2. 共享的是什么（**100% 跨端**）

| 层 | 内容 | 载体 |
| --- | --- | --- |
| **类型与校验** | 所有请求/响应的 **Zod schema**；所有领域类型 | `packages/schemas` |
| **API 客户端** | 由 **Orval** 从 Go 后端的 `openapi.json` 生成；**禁止手写请求函数** | `packages/api` |
| **异步数据语义** | **TanStack Query v5** 的 query key 规范、失效策略、错误重试口径 | `packages/api`（随生成物） |
| **客户端状态** | **Zustand** store 的**形状**（不含持久化实现） | `packages/stores` |
| **持久化契约** | `StateStorage` 适配器接口（Web 用 `localStorage`，RN 注入 MMKV） | `packages/stores` |
| **TypeScript 基线** | `strict: true` 等编译选项 | `packages/tsconfig` |

## 3. 不共享的是什么（**各端自己写**）

| 层 | Web / Tauri | Mobile（RN） | 为什么不能共享 |
| --- | --- | --- | --- |
| UI 原语 | `shadcn/ui`（Radix DOM） | `React Native Reusables` | DOM vs 原生组件 |
| 样式载体 | Tailwind CSS | **NativeWind v4** | 语法相同，**渲染目标不同** |
| 重度画布 | `@xyflow/react` | 自研轻量 Timeline 卡片 | SVG/DOM vs 原生 |
| 持久化实现 | `localStorage` | `react-native-mmkv` | 平台能力 |

> ⚠️ **NativeWind 声称"同一套 Tailwind 类名"，但那只在类名语法层成立。**
> 布局模型（flex 默认方向、`position` 语义）、可用的 utility 子集、无障碍属性**都不同**。
> **不要把"类名可复用"读成"样式可复用"** —— 这是本文件最容易被误读的一条。

## 4. 接口冻结（**最重要的约束**）

### 4.1 Go 后端 → 前端的契约

**唯一事实源 = Go 服务导出的 `openapi.json`。**

| 约束 | 判据 |
| --- | --- |
| **禁止手写 API 请求函数** | `git grep -rE "fetch\(|axios" packages/api/ --  ':!.generated'` **应为空**（`.generated` 目录之外） |
| **生成物入版本控制** | `packages/api/generated/` 必须在 `git ls-files` 中；**不在 CI 现场生成**（否则锁不住契约） |
| **契约变更必须伴随 `openapi.json` 变化** | 只改前端类型不改 `openapi.json` ⇒ 违规 |

> ⚠️ **本条依赖一个当前不成立的前提**：`services/go-user-system` 有 Swagger/OpenAPI，
> 而**主应用（Next.js）侧没有**（`ISSUE-S3-017` / #27）。
> **⇒ 生成链只能覆盖认证服务。** 主应用的 26 个 route handler **不在契约内**。
> 这是迁移前必须先解决的缺口，见 §6。

### 4.2 端与端之间的契约

| 约束 | 取值 |
| --- | --- |
| 认证令牌的传递方式 | **HttpOnly Cookie（Web）** + **Bearer（原生）** —— 见 `ADR-0016`，**本次不改变** |
| 错误形状 | 统一 `{ code, message, details? }`；`code` 用 `SCREAMING_SNAKE_CASE` 且带域前缀（`CONTRIBUTING.md` 既有约定） |
| 时间 | 一律 **UTC ISO-8601**；显示层转换 |
| 分页 | 统一 `cursor` 或 `page/pageSize`，**二选一后全端一致**（当前主应用用 `pageMeta`，见 `src/features/api/http.ts`） |

## 6. ⚠️ 前置缺口（**迁移前必须解决，否则拓扑落地)=空转**

| # | 缺口 | 证据 | 影响 |
| --- | --- | --- | --- |
| **P-1** | **主应用侧无 OpenAPI** | `git ls-files \| grep -i openapi` → **5 个命中全在 `services/go-user-system/`**；主应用 26 个 route handler 无机器可读契约 | **Orval 只能生成认证服务的 client**；主应用的业务 API **无法生成** ⇒ 「禁止手写请求函数」在主应用侧**无法执行** |
| **P-2** | **14 个页面 Server Component 直查 DB** | `grep -rl 'from "@/features' src/app --include=page.tsx` → **14** | SPA 化后这些页面**必须改走 HTTP**；而当前**没有对应的 HTTP 端点**（它们直接调 service 层） ⇒ **需要新增一批 API** |
| **P-3** | **2 个 Server Actions（33 个 action）** | `grep -rl '"use server"' src/` → **2** | Next 专有 RPC。SPA 下**没有等价物**，必须改为 HTTP |
| **P-4** | **`src/proxy.ts` 是认证网关** | `ADR-0016` / `ADR-0013` | SPA + 独立 API 下，Proxy 的「头注入 + 续期」**无宿主**；需重新设计（或改为后端网关） |
| **P-5** | **`ADR-0018` 的 T2 依赖 `output: "standalone"`** | `scripts/desktop/preflight.sh` 断言它 | 改 Vite ⇒ **该断言失效**，桌面端方案须重定 |

> **⇒ P-1 ~ P-5 是本次调整的<u>真实工作量</u>，不是"基础设施搭建"。**
> 用户建议里的「立即执行落地清单」是**从零新建 Monorepo**的步骤；
> **而本仓已有 189 文件 / 28,927 行**，路径不是「新建」而是「**拆解 + 搬迁**」。

## 9. 顺序约束（**不可交换**）

用户指定：**先 MySQL→PostgreSQL，再迁前端。**

**理由（我同意，并补一条）**：

| 理由 | 说明 |
| --- | --- |
| 用户的：认证库先稳定 | 前端迁移会重写认证交互（登录/刷新/登出） |
| **我补的**：`go-user-system` 的 **subtree** | 两件事**都要改 `services/go-user-system/**`** ⇒ 若先做前端迁移，会**在同一个子树里叠加两层本地改动**，`subtree pull` 冲突更难解 |

⇒ 顺序：**M0-1 ✅ → M1 → M0-2 → M5（切库）→ 前端迁移**。
