> **依据**：AI 协同框架 `AGENTS.md` §0.2「执行前文档同步（**双锚**）」

## 本目录是什么

框架 §0.2 规定执行前要读**两个锚**，各答一个问题、**不可互替**：

| 锚 | 位置 | 回答 | 内容 |
| --- | --- | --- | --- |
| **计划锚** | **`docs/planning/`（本目录）** | **「去哪、为什么、架构规格是什么」** | 里程碑 · 目标规格 · **接口冻结** · 多阶段路线图 |
| **足迹锚** | `docs/changes/` | 「这一步具体改了什么、为什么、怎么验证的」 | 逐次改动的前后对照与验证日志 |

外加两个参照：

| 目录 | 答什么 |
| --- | --- |
| `docs/adr/` | 「**为什么这样定**」（决策，长期；只增不改，改主意时新增并标 `superseded`） |
| `../KnowTrace-Document/KnowTrace-十环补齐/01-缺漏台账.md` | 「**还有什么没做**」（**不在本仓**，见框架 §6 多仓归属） |

## 本仓此前没有这个锚

`2026-10-16` 之前的实测：`docs/planning/` **0 文件**。⇒ 框架 §0.2 的「读计划锚」这一步在本仓**一直落到空处**。
本目录即为此补建。**与 `docs/09-delivery-plan.md` 的分工**：那份是**产品交付计划**（M0–M5 里程碑），
本目录是**架构级变更的施工方案**（分阶段、接口冻结、验收与回滚）。**两者不重复**。

## 目录约定

- 文件名：`YYYY-MM-DD-<主题>-施工方案.md`
- **必须包含**（框架 §0.2 对计划锚的四项）：**里程碑 · 目标规格 · 接口冻结 · 多阶段路线图**
- **接口冻结**是重点：一旦冻结，下游（前端 / 合约 / 客户端）即可并行；**解冻须走 ADR**
