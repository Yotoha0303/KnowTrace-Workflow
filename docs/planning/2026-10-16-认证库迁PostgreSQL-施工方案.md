## 1. 目标规格

**远期**：`go-user-system` 的存储为 PostgreSQL 18，与主应用同 DBMS，
但**保持独立实例与独立库**（不合并，见 ADR §4 Option D）。

**近期（本次变更）**：认证服务在 PG 上**功能等价于**它在 MySQL 上的行为，且
**全部 6 张表的结构与索引语义不退化**。逐列映射见 `ADR-0019` §2 的映射表——**不在本文重复**。

**明确的非目标**（本次不做，避免范围蔓延）：

| 非目标 | 理由 |
| --- | --- |
| 合并为单一 PG 实例 | ADR §4 Option D（+3~8 人·天，要拆 `ADR-0014` 的隔离论证） |
| 沉淀方言抽象层 | 会显著放大工作量；见 ADR §3 代价 1 |
| `git subtree` 去留 | 需**另立 ADR**；ADR §5.8 第 1 项 |
| 移植存量数据 | **数据源已丢失**（ADR §1.1）⇒ 本次是「重建」不是「迁移」 |
| 保留重音不敏感性 | `lower()` 只处理大小写；重音维度**已声明放弃**（ADR §5.3），登记为后续决策 |

## 2. 接口冻结（**本方案最重要的一节**）

**冻结对象：认证服务对外的 HTTP 契约。**

`ADR-0013` 定的边界是：主应用经**同源 BFF** 代理 `/api/v1/auth/*`，浏览器只拿 HttpOnly Cookie。
**本次变更<u>不得</u>触碰这条契约** —— 它是「主应用零改动」这个结论的**唯一前提**（ADR §1 表末行）。

| 冻结项 | 内容 | 判据 |
| --- | --- | --- |
| **端点集** | `/api/v1/auth/{login,logout,refresh,session}` + `/readyz` | 变更前后**逐个响应码一致** |
| **Cookie 名** | `knowtrace_workflow_access_token` / `refresh_token` | 字符串相等 |
| **原生客户端分支** | `X-Client: native` + `Authorization: Bearer` 响应体直返 token | 行为一致 |
| **环境变量名** | `DB_HOST` / `DB_PORT` / `DB_USER` / `DB_PASSWORD` / `DB_NAME` | ⚠️ **刻意的**：`config.go` 的对外契约**不叫 `MYSQL_*` 而叫 `DB_*`** ⇒ 换库**不必改**这组名字（ADR §5.4 已点名：这是一个**自带伪装的耦合点**，改名与否**在外观上不可分辨**） |

**解冻条件**：任何一项要改 ⇒ **停**，回 01 环补 ADR。**不得在实现中顺手改契约。**

**主应用侧的可核判据**：`git grep -n "3306\|auth-mysql\|mysql" -- src/` 在变更前后**均应为 0 命中**。

## 3. 里程碑与路线图

> 分阶段依据：**每完成一阶段须过 §4.2 的三跳链**（独立测试 → 负向证伪 → 转段裁决），
> **缺一则不得进入下一阶段**（框架 `AGENTS.md` §4.2）。

### M0 · 先决条件（**不做完不得开工**，人工裁定 `2026-10-16`）

| # | 内容 | 判据 | 关联 |
| --- | --- | --- | --- |
| **0-1** | **测试基建**：把 Go 集成测的 CI 门补上 | `go` job 里集成测试**真的执行**（CI 日志非 skip 用例数 > 0） | `ISSUE-S3-015` = GitHub **#25** |
| **0-2** | **备份链**：在**新建的 PG 库**上建备份，并**验收一份可恢复归档** | 恢复成功**且真实登录一次成功**（业务级，非只验行数） | ADR §5.2 ② / §5.7 |

⚠️ **顺序**：0-1 可最先做（纯准备）；0-2 需**先有 PG 库**（见 M1），故它跨在 M1 之后。
**ADR §5.2 写的是「缺一不得开工」，比它自己的内容更严**——准确说法是「**缺一不得<u>切库</u>**」（即不得做 M5）。

### M1 · 建 PG 认证库（**不碰 compose**）

按 `ADR-0019` §2 映射表建 6 张表 + 索引。**与现网 MySQL 并存，互不影响。**
**判据**：空库跑 `migrate up` 成功（这是 M2 的验收，此处只建库）。

### M2 · 迁移脚本重写（6 个 goose 文件）

**这是本次最大的改动面**，也是 ADR 互审点名的「**最弱一环**」（§5.9(b) M4：现有判据对它**没有证伪面**）。

**判据（正负成对，缺负向不算）**：

| 正向 | 负向（注入什么必须失败） |
| --- | --- |
| 空库 `migrate up` 成功 | 把 `00005` 的 `ON CONFLICT` 目标写成 `(user_id)` 而非 `(user_id, role_id)` ⇒ 重复插入**必须报错**（而非静默丢行） |
| 6 张表结构与 §2 映射表一致 | 在任一迁移里留一处 MySQL 专有语法 ⇒ **CI 必须红** |

⚠️ **注意两处易漏**（ADR 互审 S4）：
- `pkg/database/migration.go:77` 的 **`MultiStatements = true`** —— PG 无此字段，而它决定多语句文件 `00004`（7 条语句）能否一次跑通
- `internal/testutil/mysql.go:235` 的 `quoteIdentifier` **返回反引号** —— 是 ADR §3.3 所列「3 条」之外的**第 4 条** PG 不存在构造

### M3 · 驱动与 DSN

| 改动 | 要点 |
| --- | --- |
| `gorm.io/driver/mysql` → `gorm.io/driver/postgres` | 采纳 `ADR-0019` §4 Option A |
| `pkg/database/migration.go` 的 `mysqldriver` 路径 | ⚠️ **它也走 mysql 驱动**（ADR §2「两个驱动路径都要改」） |
| **`loc=Local` 的时区对齐** | **全表最危险的一处**（ADR §2）：需给出 PG 的连接级时区声明 |

**判据**：**断言落库值**，不是往返值 —— `SELECT now()` 与 `date -u` 差值 < 1s，
且在**宿主 `TZ` 与容器 `TZ` 不一致**的两种组合下各跑一次（ADR §5.6 判据 5 的修正版）。

## 4. 验收与回滚

**全部在 `ADR-0019` §5.5 / §5.6 / §5.7**，本文不复制。三条要点：

1. **回滚方案没演练过 = 没有回滚方案**（ADR §5.5）
2. **判据必须正负成对**——只有正向判据等于没有判据（ADR §5.6）
3. **恢复验收必须含真实登录**——只验行数/校验和的备份可能是「密码哈希全 NULL」而全绿（ADR §5.7）
