# ADR-0018：桌面端外壳的前提与形态选择

- 状态：**proposed**
- 日期：2026-10-05
- 扩展：ADR-0016（不改写其结论 —— Expo 原生 / token 模式 / 端上转写三项决策不变）
- 依据：`next.config.ts`（2026-10-05 实读）、`scripts/desktop/preflight.sh`（本 ADR 同日新增）、
  `docs/18-mobile-client-plan.md` §M2、§M5

> **为什么是 proposed 而不是 accepted**：本 ADR 的结论依赖一个**产品意图**——
> 「桌面端要不要支持离线记录」。那是用户/产品的判断，不是工程能替它定的。
> 所以下面把**判据**写死，把**选择**留空。

## 背景

ADR-0016 与 `docs/18` §M5 里都写着一句话：

> 桌面端用 Tauri 套用现有 Web 构建产物，不单独开发。

2026-10-05 实读 `next.config.ts` 后发现这句话的**前提不成立**：

```
output: "standalone"      ← 产物是一个 Node 服务
```

而 Tauri 的 `frontendDist` 吃的是**静态目录**。两者不是一回事：
`standalone` 产物是一个 `server.js` + `.next` 目录，要靠 Node 运行时才能起。
你没法把它当静态站点喂给 WebView。

所以「套一下就行」从来不是事实，只是一个还没被检验的假设。
`sripts/desktop/preflight.sh`（新增）把这个假设变成可执行、可证伪的判断。

## 决策

### 1. 形态必须显式选择，不得默认沿用「套现有产物」

| 路 | 做法 | 离线可用 | 代价 | 判定 |
| --- | --- | --- | --- | --- |
| **T1** 静态导出 | `output: "export"` | 是 | **关掉 Server Actions 与动态路由** —— 等于重写业务逻辑 | **否**（违反 ADR-0016「复用服务端，不重写」） |
| **T2** 进程内 Node sidecar | 打包 Node 运行时 + `standalone` 产物，Tauri 壳管理其生命周期 | **是** | 体积约 +60–100 MB；要处理进程生命周期、端口分配、崩溃重启 | 候选 |
| **T3** 加载远程 URL | 窗口直接指向 `https://…` | **否** | 改动最小 | 候选 |

### 2. 选择的判据（只有一条）

> **桌面端是否需要「断网也能记录」。**

- **需要 → T2**。没有第二条路：静态导出被否，而 T3 在断网时连界面都出不来。
- **不需要 → T3**，但**必须在文档里写明「这不是桌面应用，是一个没有地址栏的浏览器窗口」** ——
  否则日后会被当成「已经支持离线」，而那是没有的事。

### 3. 倾向 T2，理由是**与既有承诺一致**

`docs/18` §M2 已经把「本地 SQLite 写入队列，先落本地再同步」列为移动端的必做项。
**如果桌面端反而不能离线记录，那么同一个用户在两端的采集行为会不一致** ——
而「随手记录」正是这个产品的主路径（`docs/00-product-brief.md`）。

另外，桌面端真正说得出口的存在理由是**系统级采集入口**（全局热键、截图、拖拽、托盘），
那全部是 OS 集成。一个**断网就录不进去**的采集入口，在最需要它的场景里失效。

**所以：若无相反的产品理由，采纳 T2。** 但 T2 的工作量比 M3 + M4 加起来还大，
必须单独排期，不能藏在 §M5 的一行里。

### 4. 无论选哪条，以下三件事都需要各自的决策（本 ADR 不覆盖）

1. **代码签名与更新** —— 「能直接推向市场接受商业检验」意味着：
   未签名时 Windows SmartScreen 会拦下每一台机器；没有 updater 就每次手动发版。
   这两条**恰好有自然时机**（每次 release），符合本项目「能自动就别人工」的原则，
   应设计成发布流水线的一步。需要单独决策（证书、更新源、灰度）。
2. **凭据存储** —— ADR-0016 已写死「不得使用明文或非加密存储」。
   桌面端对应的是系统凭据库（Windows Credential Manager / macOS Keychain）。
   **这是一个可以进 CI 的断言面**：断言凭据不落到磁盘明文路径。
3. **不得为桌面端新开接口** —— `docs/18` §6 已写明「不允许出现只有 App 才能验证的接口」。
   桌面端新增能力必须同时补 `/api/v1` 契约测试，这样才能进 CI，而不是又一个门外用例。

## 后果

- `docs/18` §M5 不再写「Tauri 套现有产物」，改为指向本 ADR。
- `scripts/desktop/preflight.sh` 断言当前形态是 `standalone`；
  一旦有人改成静态导出，它**失败**（已做负向验证：改 `export` → exit 1）。
  那个失败不是「脚本坏了」，是「桌面端前提变了，要重评」。
- 本 ADR 处于 `proposed` 期间，**桌面端不进入实施**。缺的是决策，不是代码。
- ADR-0016 的三项决策（Expo 原生 / token 模式 / 端上转写）**不受影响**，未被 supersede。
