# ADR-0021：部署形态裁定——优先双轨，托管为兜底，自托管资产不得删除

- 状态：**accepted**（`2026-10-22`，人工裁定）
- 日期：2026-10-22
- 关联：`ADR-0004`（Next.js 全栈单体，继续有效）· `ADR-0019`（认证库迁 PostgreSQL）· `ADR-0020`（证据图片双驱动，双轨的第一个落地实例）

## 1. 背景

台账 `DEFER-005` 长期记着「部署目标未定」，与仓库自述**不一致**：`README.md` 已宣称
生产跑 **Vercel + Render + Supabase**，并同时把**单机 12 容器自托管**列为另一条拓扑。
两处不同成熟度的事实并存（违反 D4），必须裁定。

实测现状：

| 事实 | 值 |
| --- | --- |
| 生产（托管） | 在线：`https://knowtrace-workflow.vercel.app`（health 200） |
| 自托管资产 | **83 个入库文件**仍在仓内（compose / deploy / scripts / Dockerfile / Makefile） |
| 自托管轨道**最近一次真实运行** | **`2026-10-08` 之前**；此后 VPS 停机且不续，认证库随之丢失（`ADR-0019` §1.1） |
| 本工作区能否跑自托管轨道 | **否**——本机无可用 Docker（已登记事实） |

## 2. 决策

1. **优先双轨**：`README` 所述两条拓扑**均为产品形态**，长期并行维护。
   - **拓扑 A（托管）**：Vercel + Render + Supabase —— **生产在线形态**。
   - **拓扑 B（自托管）**：单机 Docker Compose（含 `deploy/` 的 Caddy/nginx/Prometheus/Loki 等）。
2. **兜底顺序**：若双轨在某处**不可行**（成本、时间、维护力不足），**优先保留拓扑 A（托管）**，
   即「否则就是方案 2」。
3. **不得删除原有文件**（硬约束）：`compose.yaml` · `compose.production.yaml` · `deploy/**` ·
   `scripts/linux/**` · `scripts/ops/**` · `Dockerfile` · `Makefile` 等**自托管资产一律保留**。
   即使将来临时停摆，也只能**标注为「暂未验证」或「冷备」**，**不得删除、不得静默改写为徒有其名的空壳**。
4. **双轨的判据不是「两边都能启动」**，而是**每条关键能力在两条拓扑下各有一个可执行判据**。
   `ADR-0020`（证据图片 local / vercel-blob 双驱动）是第一个按此要求落地的实例：
   本地驱动由 CI 的 e2e 覆盖，云端由平台实测覆盖，**两条各有判据**。

## 3. 后果与代价（如实）

| 项 | 内容 |
| --- | --- |
| **正面** | 数据敏感/私有化场景可用；与 `README` 自述一致；避免为单一平台锁死（本次图片存储问题正是平台差异的直接后果） |
| **代价 1：验证面积翻倍** | 每项能力都要在两轨验证。为把成本压住，允许**分优先级**：托管轨（生产）为 P0，自托轨可滞后，但**必须留明确判据**，不得只靠"应该能跑" |
| **代价 2：自托轨当前**「未验证」 | 自 `2026-10-08` 起没有真实运行，本机也无 Docker。**这不等于它坏了，但也不等于它好**——任何引用须标「未验证」 |
| **代价 3：外部前置未完成** | `docs/CICD-待完成.md` 的 **E1–E4**（备份定时器开关、认证 e2e 人工触发、`EXPECTED_SERVICES`、异地备份凭据）都是**主机侧动作**，双轨下仍然适用 |

## 5. 判据（可证伪）

1. **不得删除**：`git ls-files compose.yaml compose.production.yaml deploy scripts/linux scripts/ops Dockerfile Makefile`
   的条目数**不得减少**（除另立 ADR 显式取代本决策）。当前基线：**83 个入库文件**（`2026-10-22` 实测）。
   ⚠️ **该判据目前无机械守卫**——已登记 `KT-DEFER-017`。
2. **不得静默降级**：若某拓扑被临时停摆，必须在 `README` 与 `docs/11-operations.md` 同轮标注
   「暂未验证 / 冷备」，且 `docs/14` 有对应条目。只改代码不改文档 = 未完成（D4）。
3. **兜底触发可判**：只有在给出「双轨中某轨不可行的具体事实」（如自托管所需机器长期不存在，
   或维护成本有可量化数字）时，方可执行兜底；**不得**以「麻烦」为由单方面收敛到单轨。
4. **负向用例**：注入「删除 `deploy/` 下任一文件」的变更 ⇒ 若 CI 或评审未拦下，则本条判据不成立；
   在 `KT-DEFER-017` 落地前，该项由评审人工执行并在 PR 里留痕。

- `KT-DEFER-011` 第 2–3 条的修复排期（已解除阻塞，未排期）。
