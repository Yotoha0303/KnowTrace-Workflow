## 1. 背景

`ADR-0014` 把 `go-user-system` 以 `git subtree` 纳入 `services/`，并定下「MySQL、Redis、
PostgreSQL 保持独立数据卷」。那个决定只说明了**分开部署**，**没有说明为什么认证库用 MySQL**。

实测现状（2026-10-16）：

| 事实 | 证据 |
| --- | --- |
| 主应用已是 PostgreSQL 18 | `drizzle.config.ts:9` `dialect: "postgresql"`；`compose.yaml:20` `postgres:18-alpine` |
| 认证服务是 MySQL，驱动写死 | `go.mod:8,20` `go-sql-driver/mysql` + `gorm.io/driver/mysql` |
| goose 方言写死 | `cmd/main.go:76` `goose.SetDialect("mysql")` |
| **同一服务的 MySQL 主版本在 4 处冲突** | 根 `compose.yaml:37` 与两个 CI = `8.0`；服务自建 `compose.yaml:5`、`k8s/mysql.yaml:34`、`Makefile:282,284` = `8.4` |
| 排序规则也不一致 | `migrations/00001` 用 `utf8mb4_0900_ai_ci`；`k8s/mysql.yaml:55` 用 `--collation-server=utf8mb4_unicode_ci` |
| 主应用**从不读取**认证库 | `git grep -n "3306\|auth-mysql\|mysql" -- src/` → **0 命中**；两库间**只有 HTTP**（`AUTH_SERVICE_URL`） |

⇒ 结果是**两种 DBMS 并存**，而主应用侧原本就要维护一套 PG 的迁移、备份、恢复、巡检工具链。

### 1.1 一条改变前提的事实：存量数据已不可用

认证库随生产服务器于 **2026-10-08 停机且不续**而丢失：

| 检查 | 结果 |
| --- | --- |
| 本机是否有认证库备份 | ❌ **无**——`_ops-backups/` 只有 ops-toolkit / 证据报告 / TSDB / ledger，**无任何 MySQL dump** |
| 本机 MySQL 实例 | ❌ 无 |
| 本机 Docker | ❌ 无 |

**⇒ 本次不是「迁移存量数据」，而是「用 PostgreSQL 重建认证库」。**
这一条改变了本文的形态：**无数据搬迁章节**、回滚更简单（无旧数据要保），且
**没有可 `superseded` 的对象**（当年为何选 MySQL 无 ADR，故本文只能是**新决策**）。

> 停机前最后一次快照显示认证库只有 `users=1` / `roles=2`（`KnowTrace-Document/KnowTrace-十环补齐/10-服务器到期前收尾盘点.md`）。
> **该数字当前无法复核**（机器不存在），故**不作为决策依据**，只作量级参考。

## 2. 决策

**把 `go-user-system` 的存储从 MySQL 改为 PostgreSQL**，与主应用**同 DBMS、同版本线（18）**，
但**保持独立实例与独立库**（不合并为单库，见 §4 Options D）。

### 为什么做

1. **统一 DBMS**：一套迁移/备份/恢复/巡检工具链，而不是两套。判据是可测的——
   `monthly-ops` 演练要同时拉的镜像从 3 个（postgres/mysql/redis）降到 2 个。
2. **消掉 §1 表里那两处 SSOT 漂移**（版本 pin 冲突、排序规则不一致）——它们会被本次一并收口。
3. **主应用零改动**：两库只有 HTTP 耦合，这是 `ADR-0014` 已经付过的解耦成本，现在兑现收益。

### 目标 schema（逐列类型映射）

**这张表是换库最容易出错的地方**，逐条给出「MySQL → PG」与**必读语义差**：

| 表.列 | MySQL | PostgreSQL 目标 | ⚠️ 语义差（必须知道） |
| --- | --- | --- | --- |
| `*.id`（4 处） | `BIGINT AUTO_INCREMENT` | `bigint GENERATED BY DEFAULT AS IDENTITY` | **不用 `serial`**（`serial`=`integer`+隐式序列，`bigserial` 才是 bigint）。用 `BY DEFAULT` 而非 `ALWAYS`，因为 `00004`/`00005` 需要**显式插 `role_id`/`permission_id`** |
| `users.status` | `TINYINT NOT NULL DEFAULT 1` | **`smallint`** | **不要 `boolean`**：Go 侧是 `int8`，且**现有值是 `1/2` 不是 `0/1`**——`boolean` 会把 `2` 判为非法 |
| `*.created_at/updated_at/last_login_at/deleted_at/expires_at/revoked_at`（14 处） | `DATETIME(3)` | **`timestamptz(3)`** | **全表最危险的一行**。MySQL `DATETIME` **无时区**，靠 `db.go:47` 的 `loc=Local` 按进程本地时区解释；PG `timestamptz` 存**绝对时刻**。搬迁/重建时若源时区声明错，**时间平移而每一层类型检查都过**。`refresh_tokens.expires_at` 用它判过期 ⇒ **平移 = 会话提前/延后失效，是安全事件** |
| `*.username/code/name/jti/token_hash/...` | `VARCHAR(n)` / `CHAR(64)` | 同宽 `varchar(n)` / `char(64)` | **排序规则变了 ⇒ 唯一键语义变了**。现库是 `utf8mb4_0900_ai_ci`（**大小写不敏感**），PG 默认大小写**敏感**。⇒ `unique(username)`、`uk_roles_code` 等在 MySQL 下 `Alice`/`alice` **冲突**，迁到 PG **不再冲突**——**这是唯一约束的静默放宽**。缓解：`CREATE UNIQUE INDEX ... (lower(username))` 或列级 `COLLATE "und-x-icu"`（**PG 18 上的可用性待实测**） |
| `user_roles(user_id, role_id)` 等复合主键 | `PRIMARY KEY (a,b)` | 同 | 无差异 |
| 字符集 | `utf8mb4` | `UTF8` | PG 的 `UTF8` = 完整 Unicode，**等价于** MySQL 的 `utf8mb4`。**注意**：`CREATE DATABASE ... ENCODING 'utf8mb4'` 会报错 |
| `ENGINE = InnoDB` / `CHARSET` / `COLLATE` | 6/12/6 处 | **删除** | 库级设定 |
| `ON UPDATE CURRENT_TIMESTAMP` | **实测 0 处** | — | **无需映射**：时间戳由 GORM 的 `autoCreateTime`/`autoUpdateTime` 标签负责 |
| `INSERT IGNORE`（4 处） | | `INSERT ... ON CONFLICT DO NOTHING` | — |
| `ON DUPLICATE KEY UPDATE ... VALUES(x)`（2 处） | | `ON CONFLICT (…) DO UPDATE SET x = excluded.x` | `VALUES()` 自 MySQL 8.0.20 已 deprecated |
| `NOW(3)`（20 处） | | `now()` | PG 原生微秒精度 |
| `MODIFY COLUMN`（1 处） | | `ALTER COLUMN … TYPE …` / `SET NOT NULL` | — |
| `AFTER <col>`（4 处） | | **删除** | PG 无列序概念 |
| `DROP KEY`（1 处） | | `DROP INDEX` | — |

**保留的净收益**：MySQL 的 DDL 隐式提交使每个迁移文件都必须写 `-- +goose NO TRANSACTION`；
**PG 的 DDL 是事务性的**，去掉该行后可获得「**迁移失败自动回滚**」。

### 两个驱动路径都要改（易漏）

1. **GORM**：`pkg/database/db.go:11` `gorm.Open(mysql.Open(dsn), …)` → `gorm.io/driver/postgres`。
2. **⚠️ 迁移路径不经 GORM**：`pkg/database/migration.go:17,64-70,84` 用 `database/sql` +
   `mysqldriver.NewConfig()` + `FormatDSN()`，那是 `migrate up` / `bootstrap-admin-if-needed`
   两个子命令的**唯一** DB 入口。
   ⇒ **`github.com/go-sql-driver/mysql` 不能从 `go.mod` 删掉**，除非把这一整个文件也换掉。

## 3. 决策依据与代价

**依据**：主应用侧已有一套成熟的 PG 工具链（`scripts/migrate.mjs` 带 sha256 校验、
`backup-all.sh` 含逐表行数清单、`verify-restore.sh` 在临时容器逐表比对）。
复用它的收益是**可测的**，不是偏好。

**代价（如实列，不淡化）**：

1. **`git subtree` 的长期成本**：`services/go-user-system` 是 `git subtree` 引入的上游副本
   （`ADR-0014` §「更新上游源码」给的是 `git subtree pull`）。改成 PG 后，本地适配面积
   从「几处」扩大到约 40 个文件 ⇒ **每次 `subtree pull` 都会冲突，且没有到期日**。
   **本 ADR 不解决它**，只在 §5 记为待决。
2. **方言依赖是语法性的，`grep` 查不出来**：实测
   `git grep -l -i mysql -- services/go-user-system/migrations/` → **0 个文件**，
   而方言语法确实在里面（`AUTO_INCREMENT`×4 · `utf8mb4`×12 · `DATETIME(3)`×14 …）。
   ⇒ **任何"grep 过没有 mysql 了"的收尾声明在本仓不可信**，收尾判据必须是 §4 的负向用例。
3. **测试基建有 PG 里不存在的语句**：`internal/testutil/mysql.go:135,139`（`SET FOREIGN_KEY_CHECKS`）、
   `:200`（`SELECT DATABASE()`）、**`:213`（`SELECT GET_LOCK(?,30)`）**——最后一条最阴：
   MySQL 返回 `1/0`，`pg_advisory_lock` 返回 `void` ⇒ `:216` 的 `if lockResult != 1`
   **编译不过或永远为假**。
4. **验证面当前是空的**：CI 刻意不配 `TEST_DATABASE_DSN`，集成测试全部 `t.Skipf`
   （`ci.yml:120-121` + `testutil/mysql.go:91`）。**换库最需要的那类证据不在任何门里**（见 §5 先决）。

## 4. Options（含被否方案与理由）

| # | 方案 | 裁定 | 理由 |
| --- | --- | --- | --- |
| **A** | **`gorm.io/driver/postgres`** | ✅ **采纳** | 与现有 `gorm.Open(...)` 链一致，改动面最小；GORM 链实测**方言中立**（全服务只有 4 处 `clause.*`，无一处 `OnConflict`/`UpdateAll`/`Returning`） |
| **B** | `pgx` v5 直连 | ❌ 否 | 性能更好，但要绕过 GORM 重写 DAO 层；本服务的负载（`users=1`、`refresh_tokens` 少量）**用不上**。**若将来 DAO 层要重写，可另立 ADR** |
| **C** | 保留 MySQL，只统一版本 pin | ❌ 否 | 只解决 §1 的一半问题（版本冲突），**不解决两套工具链**；且与主应用仍是两套方言 |
| **D** | 合并为**单一 PG 实例**（同实例不同库/不同 schema） | ❌ **本次不采纳** | 收益是把「灵活性」从**一次性可行**变成**结构性解耦**；代价 +3~8 人·天，且要重建 `ADR-0014` 的隔离论证（"独立数据卷"是它刻意选的）。**本次先不扩大范围**——若日后要做，另立 ADR 并处理与 `0014` 的取代关系 |
| **E** | 移植存量数据（`mysqldump` → 转换 → `psql`） | ❌ **不可行** | 数据源已随停机丢失（§1.1）。**不是"次优"，是做不到** |
| **F** | 双写 / 影子写 | ❌ 否 | 认证写路径是 JWT refresh token 的**单次使用 + 家族吊销**，跨两库双写**无法保证 token 不被重复消费**。拿**认证正确性**换**不存在的可用性收益** |

## 5. 后果

### 必须一并解决的先决条件

**`KT-GAP` 同族 / `ISSUE-S3-015`：先把 Go 集成测的 CI 门补上。**
不补，则 §4 的每一道负向判据都**没有载体**——把方言改错，**单测照样全绿、集成测照样 skip**。
判据：`go` job 里集成测试**真的执行**（CI 日志里非 skip 的用例数 > 0）。

### 三处 SSOT 漂移必须同步收口

| # | 漂移 | 收口判据 |
| --- | --- | --- |
| 1 | MySQL 版本 pin 4 处冲突（8.0 / 8.4） | 迁移后应**只剩一个 PG 版本值**（`postgres:18-alpine`），`grep -rn "mysql:8\." ` **应为空** |
| 2 | 排序规则不一致（`_0900_ai_ci` vs `_unicode_ci`） | 统一到 PG 的显式 `COLLATE`，并在文档写明 |
| 3 | `.env.goose.example` 的 `GOOSE_DRIVER=mysql` 与写死 `127.0.0.1:3306` | 随驱动一并改 |

### 运维链必须同步改（**回滚能力依赖它**）

备份/恢复脚本全部绑死在 MySQL（`scripts/backup-auth.ps1`、`scripts/linux/backup-all.sh` 的
`mysql_counts()`、`verify-restore.sh`、`services/go-user-system/scripts/ops/*`、`monthly-ops.sh`）。
**必须在迁移的同一个变更里改完**——否则**回滚能力在迁移那一刻消失，而那正是最需要它的时候**。
其中 `verify-restore.sh:201` 的逐表行数 `cmp` 判据与 `backup-auth.ps1` 的
「容器内 sha256 → cp → 主机 sha256 → manifest」四步校验**必须保留**（它是本项目唯一挡住
「0 字节备份」的机制——见 `AGENTS.md` §8.1 ①）。

### 回滚策略（**三档，且必须演练**）

数据源已丢，故回滚比常规换库**简单**，但仍有档：

| 档 | 动作 | 前置 |
| --- | --- | --- |
| R1 应用回滚 | `git revert` 本次改造 → 用 MySQL 镜像重建空库 → `auth-bootstrap` 重放管理员 | MySQL compose 定义**不得先删** |
| R2 库回滚 | 无旧数据可回 ⇒ 等同 R1；若观察期内已产生数据，按新建库的备份还原 | 观察期内的备份链已改好 |
| R3 冷备 | 迁移前对**空/新库**做一次基线备份 | — |

> **判据：回滚方案没演练过 = 没有回滚方案。** 本项目的 `verify-restore.sh` 已有
> 「在无端口、无生产卷的临时容器里恢复并比对」的形态，本次演练复用它。

### 验证判据（可证伪，正负成对）

| # | 正向 | **负向（注入什么必须失败）** |
| --- | --- | --- |
| 1 | `/readyz` 返回 200 且真实登录一次成功 | 把 `DB_HOST` 指向不存在的服务 ⇒ **必须 fail closed**（`ADR-0013`：不得降级为匿名） |
| 2 | `roles=2 / permissions=6`，`admin` 关联 6 个权限、`user` 关联 3 个 | 删掉一条 `role_permissions` ⇒ **权限校验必须失败** |
| 3 | 全仓 `grep -rn "mysql" -- services/go-user-system/` 只剩历史文档 | **`grep` 不是判据**（§3.2）。真判据：在 `testutil` 里写一条 MySQL 专有语法 ⇒ **CI 必须红** |
| 4 | 大小写：建 `Alice` 后再建 `alice` | MySQL 下**必须被唯一键拒绝**；PG 下**必须复现同一行为**（否则唯一性语义已被静默放宽） |
| 5 | 时间：写入一条 `expires_at` | 在**两个不同时区**下读回 ⇒ **必须得到同一绝对时刻**（这是 §2 时区行的判据） |

### 未决（**不在本 ADR 范围内**）

1. **`subtree` 去留**：接受长期冲突 / 转 fork / 把改造做成上游补丁推回。**+2~5 人·天外加上游协调**。需**另立 ADR**。
2. `users.id = 1` 的保号：主应用以 `created_by_id = 'go-user:1'` 引用（`drizzle/0020` 等），跨库**无外键**。
   重建后**必须实测确认**新 `auth-bootstrap` 建出的管理员 `id` 确为 `1`，否则那批内容会**静默换主**。
3. `PG 18` 上 `COLLATE "und-x-icu"` 的可用性——**待实测**。
4. 生产容器的 `TZ` / `/etc/localtime`（`compose.yaml` 的 auth 段**没有设 `TZ`**）——它决定时区映射的源端声明。

## 6. 分档与流程（**本仓第一次走正式档位**）

按「爆炸半径 × 可逆性」分档，本变更属 **C 档（架构级）**：

| 档 | 判据 | 需要什么 |
| --- | --- | --- |
| A | 加性 / 可逆 / 不锁表 | PR + 迁移脚本 + 代码审查（**不需要 ADR**） |
| B | 破坏性 / 需停机 / 难回滚 | + 变更方案 + 回滚脚本 + 演练 |
| **C** | **换 DBMS / 分库分表 / 改一致性模型 / 改数据归属** | **ADR + 变更方案 + 迁移与回滚脚本 + Runbook + 演练 + 变更窗口** |

**四类产物回答不同的问题，不可互替**：

| 产物 | 回答 | 本文是 |
| --- | --- | --- |
| **ADR** | **为什么**这么选（对比过什么、权衡是什么） | ✅ **本文** |
| 变更方案 / 技术设计 | **改成什么样**（类型映射、兼容矩阵、分阶段） | 本文 §2 已含映射表；施工顺序待补 |
| 迁移 + 回滚脚本 | **怎么执行**（可执行、版本化、正反成对） | ⬜ 待补（02 环） |
| Runbook / 变更单 | **谁在什么窗口做什么、什么条件中止、谁批** | ⬜ 待补 |
