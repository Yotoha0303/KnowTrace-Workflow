## 1. 它解决什么问题

KnowTrace-Workflow 面向一个很具体的困境：**你脑子里有东西，但一打开笔记软件就要先想"放哪个文件夹"**。

它的处理方式是反过来的：

> **先原样存下来，整理可以以后再做。**

你输入关键词、半句想法、一段经历、一个观察或一个问题，**直接保存，不要求你选分类、填标题、套模板**。
之后你可以手动分类，也可以让 AI 给你一批**候选**建议（标题、摘要、内容类型、分类、局部改写），
你逐条决定要不要。

**核心承诺是一条**：

> **AI 失败不影响你保存。原文永远不被 AI 覆盖。**

【依据：文件】`README.md` 的核心约束与 `00-product-brief.md` 的产品原则第 1、3 条。

## 2. 日常怎么用

### 2.1 记录（这是唯一必须会的操作）

```
输入内容 → 可选填「描述对象」和「发生时间」 → 保存（或 Ctrl/⌘+Enter）
```

- **发生时间**默认为当前时间，但可以调——它表示**内容描述的事件发生在什么时候**，
  不等于你记录的时间。这两者分开保存。
- **描述对象**是自由文本（公司、人物、项目），会参与检索，可以回看某个对象的时间线。

### 2.2 整理（可做可不做）

- 手动分类：一条记录可以属于多个分类。
- AI 整理：主动触发，AI 给你**候选**结果，你逐条接受、修改或拒绝。
- 接受 AI 的局部改写前，你会看到**整篇的修改前/修改后对比**；采纳后如果还没做后续修改，可以**整体回退**。

### 2.3 检索与回看

- 统一检索：跨记录、主张、证据和人工结论一起搜。
- 分类主题档案：按分类看聚合进展。
- 相似记录：按同一对象、共同分类和文字片段找，**只用于回看**，不代表观点一致。

## 3. 信任边界：这部分请务必读完

KnowTrace-Workflow 在「可靠性」这件事上**极其克制**，它的克制是有意的。作为使用者，你需要知道
**它声称什么、不声称什么**。

### 3.1 普通记录**不是**「已验证的知识」

你保存的任何记录，都只是**你写下的内容**。系统不会、也不应该因为 AI 处理过它就提升它的可信度。

- AI 的 confidence 数字**只是排序依据，不是真实性评分**。
- 界面上不存在一个含糊的「已验证」按钮。这是刻意的。

### 3.2 「证据链」在说一件很窄的事

KnowTrace-Workflow 最独特的部分是**主张 → 证据 → 独立复核 → 可靠发布**这条链。它在说的是：

| 系统能证明的 | 系统**不能**证明的 |
| --- | --- |
| 某个来源**当时可以访问** | 这个来源**权威** |
| 摘录**确实出现在**抓取到的内容里 | 这个主张**正确** |
| 结论**用过哪些证据、哪个版本** | 结论**永远成立** |
| 复核者**是另一个登录账号** | 复核者**判断对了** |

**「摘录匹配」不等于「来源可靠」**，这是项目里被反复强调的一条【依据：文件】`10-risk-register.md` R-17。

### 3.3 这条链当前的验证状态

【实测】生产库：

```
知识发布（knowledge_releases）        0
独立复核（independent_claim_reviews）  0
人工结论（claim_reviews）              0
来源检查（evidence_source_checks）     0
```

**这条链是 KnowTrace-Workflow 区别于普通笔记工具的地方，机制侧已经完整建成**：
严格状态机、八项发布门槛、来源权威性评估、复核者身份分离都有对应实现与测试覆盖。
**但线上还没有一条真实主张走完过它**——当前状态是「已实现、未行使」。

而且它有一个硬前提：**独立复核必须由不同的登录账号完成**，而当前实例**只有 1 个账号**。
**在你建出第二个账号之前，这条链不会在你的实例上被行使。**

> **给你的建议**：现在可以用它做记录整理，稳定可用。等你打算把某条结论当作「可引用的知识」
> 时，先按第 8 节的方式建第二个账号、把这条链走完一遍——那时候你得到的不是一个功能开通，
> 而是一条**你自己验证过的**信任链。

## 4. 不在当前产品范围内的能力

下表是**产品层面的有意取舍**，不是待修的问题：

| 不在范围内 | 原因 |
| --- | --- |
| **直接暴露到公网给匿名用户** | `00-product-brief.md` 明确「不适用」。部署面向本机或受保护的可信网络 |
| **移动 App** | 尚未开发。`/api/v1` 契约已就绪，执行方案见 `docs/18`，但 UI 不存在 |
| **真 · 自动事实核查** | 明确不做。「AI 对可靠性的判断只能是建议，不能自动改变证据或人工结论」 |
| **知识图谱 / RAG 问答** | 明确不做（ADR-0011/0012：当前规模下是过度设计） |
| **组织/多租户协作** | 有 Workspace 隔离，但没有组织邀请、计费、细粒度角色权限 |
| **真实身份归因** | 有创建者与审核者留痕，但**普通记录编辑尚未形成完整操作者审计** |

## 5. 隐私与数据隔离的真实情况

这部分**不能靠猜**，以下是实际行为：

- 业务数据按 **Workspace** 隔离，且同时经过**资源级**访问策略校验。
- **管理员**可读取和管理全部内容；管理员创建或导入的记录**默认对所有已登录成员共享**。
- **普通成员**只能管理自己的内容，可以**只读**查看管理员共享的内容，**看不到其他普通成员的私有内容**。
- 跨成员访问私有 UUID **按不存在处理**（不泄露「存在但无权」）。
- 详情、搜索、分类、对象时间线、导出、证据图片**复用同一读取规则**——不是只修了首页列表。

> [!WARNING]
> **「已登录」不等于「已隔离、已审计」。**
> 【实测】隔离机制完整，但**从未在真实多用户场景下被验证过**（`docs/19` D-05）。
> 当前实例只有 1 个账号，所以隔离规则**在生产上没有被行使过**。

## 6. 已知会撞上的问题（截至 2026-10-01）

| 症状 | 状态 |
| --- | --- |
| 保存时偶发「找不到数据库」错误页 | **✅ 已修**（2026-10-01，D-03 核心两项）。真实原因是 15 分钟令牌过期后被错误页显示成数据库故障 |
| 图片上传 100% 失败 | **✅ 已修**（2026-09-30，D-01）。根因是目录属主错配，**与图片格式无关** |
| AI 只会改错别字、不结构化 | **✅ 已修**（2026-09-30，D-02）。真实原因是线上跑的是本地规则模拟，不是真模型 |
| 登录偶发报「账号或密码错误」 | **✅ 已修**（2026-10-01，D-08）。真实原因是限流按容器 IP 计数，所有人共用一个桶 |
| AI 整理很慢 | **未解决**。真实模型延迟 **7–20 秒**，且异步化尚未实现 |
| 多用户隔离未经验证 | **未解决**。需要第二个账号才能真正测 |

> **这些"已修"的共同点值得注意**：上面的症状，**报告人的初步推断几乎都是错的**
> （猜图片格式、猜密码错、猜数据库故障）。真实根因都在别处。
> 这本身就是这个产品在劝你做的事：**先记录，再判断**。

## 7. 费用与凭据

- **默认不需要 API Key**：默认使用本地规则引擎模拟 AI，用于验证完整审阅流程。**它不代表事实核验。**
- **想用真模型**：可在记录详情的「AI 整理台」直接输入 OpenAI / DeepSeek 的 Key，
  或在 `.env` 配置服务端后备值。
- **界面输入的 Key 不落库**：只随本次请求发送，不写入数据库、AI Run、日志或环境变量。
  勾选「仅在当前浏览器标签页记住」后写入 `sessionStorage`，关标签页即失效。
- **支持 CC-Switch 本地路由**：供应商 Key 与 OAuth token 继续由 CC-Switch 管理，**不应复制到 KnowTrace-Workflow**。

## 8. 部署前必须做的事

> [!IMPORTANT]
> **自托管 ≠ 可以裸奔上线。**
> `README.md` 与 `SECURITY.md` 都要求先完成加固；`SECURITY.md` 三项前提
> （HTTPS 终结、网络隔离、部署加固）**全部落实后才可对外**。

部署到局域网或公网**之前**：

1. **更换初始化凭据**（默认管理员 `KnowTrace-Workflow` / `KnowTrace-Workflow@123` 只适合本机首次登录）。
2. **启用 HTTPS**，并把 `AUTH_COOKIE_SECURE` 改为 `true`。
3. **完成网络隔离与访问控制**（反向代理 / VPN / 防火墙）。
4. 🔥 **先执行 `scripts/linux/fix-uploads-ownership.sh`**——
   否则图片上传会**静默失败**（这个坑曾静默发生 42 次，见 D-01）。

**凭据卫生**：按项目既有判据，**曾出现在聊天/日志中的凭据应作废重发**。
2026-10-01 已对应用账号与 Grafana 执行过一轮轮换，新部署时同理。

**建第二个账号**：独立复核要求结论作者与复核者不是同一身份，因此想让
「主张 → 证据 → 独立复核 → 可靠发布」这条链真正跑起来，需要一个额外的登录账号
（账号管理见 `docs/12-mobile-api.md` 与账户中心）。

## 9. 一句话结论

> **KnowTrace-Workflow 是一个"记录优先、AI 辅助整理"的知识工作流系统：记录、检索、
> AI 整理、Workspace 隔离这些部分已建成且日常可用；主张—证据—复核—发布这条链
> 机制完整、测试覆盖，只是**线上还没有真实主张走完过**——这条链要不要用、值不值得用，
> 取决于你自己跑一遍的结果。**
>
> 这个项目在「讲清楚自己验证到哪一步」这件事上做得比大多数产品好：
> 它不把「已实现」写成「已验证」，每一处能力都标了证据等级。
