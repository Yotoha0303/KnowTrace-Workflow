这里的文档重点是“实际做过什么、看到什么、下一步要检查什么”。如果没有保存命令输出或截图，只记录为操作事实，不把结果描述成已验证通过。

## 记录原则

- 巡检记录写明日期、环境、操作、观察结果、处理动作和遗留风险。
- 资源、容器、监控和日志检查要尽量保留关键输出或截图。
- 停止、重启、删除容器或修改配置前，应说明原因和影响范围。
- 不在文档中保存密钥、Token、Cookie、完整 `.env` 或真实用户敏感数据。
- 只把已经实际验证的内容写成“已完成”；推断和计划要明确标注。
- **日志栈相关**：2026-10-03 起是 PLG（Alloy + Loki），**常驻**。
  写新记录时不要沿用「启动/停止 ELK」那套说法。
