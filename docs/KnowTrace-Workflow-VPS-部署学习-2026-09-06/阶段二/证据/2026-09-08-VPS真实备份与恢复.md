## 业务数据边界

线上只读 SQL 显示 `captures=1`、`evidence_attachments=0`；上传目录的 1 个文件是仓库占位文件 `.gitkeep`，不是用户附件。因此 `UPLOAD_FILES=1` 不能写成“真实附件恢复成功”。

阶段一后管理员密码已经修改，`.env` 里的初始化密码按设计不再有效；使用它登录返回 401。我没有打印凭据，也没有重置用户密码。数据库计数只能证明数据被导出和恢复，不能代替浏览器/API 业务读取。

## 常用验证命令

```bash
sudo systemctl status knowtrace-backup.timer --no-pager
sudo systemctl list-timers knowtrace-backup.timer --all
sudo tail -n 80 /var/log/knowtrace-backup.log
sudo sha256sum -c /var/backups/knowtrace/<归档名>.sha256
sudo /opt/knowtrace/scripts/linux/verify-restore.sh /var/backups/knowtrace/<归档名>
```

不要用 `docker compose down --volumes` 排障或恢复；它会扩大数据损失风险。

## 回滚

定时任务如需暂停，应先保留已有归档，再执行 `systemctl disable --now knowtrace-backup.timer`；恢复时重新启用 timer。回滚脚本版本只回到已记录 commit，不删除 `/var/backups/knowtrace`，且回滚后必须重新执行一次隔离恢复验证。
