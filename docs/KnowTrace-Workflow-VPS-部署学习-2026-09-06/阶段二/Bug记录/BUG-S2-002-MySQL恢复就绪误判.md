# BUG-S2-002：MySQL 恢复就绪探测误判

- 发现时间：2026-09-07。
- 环境：本地隔离恢复容器，MySQL 8.0.46。
- 严重度：高；恢复脚本可能在初始化完成前导入并失败。
- 状态：已修复并通过本地隔离回归，VPS 待验证。

## 现象

恢复脚本刚启动临时 MySQL 即进入导入，返回：

```text
ERROR 1045 (28000): Access denied for user 'root'@'localhost' (using password: YES)
```

同样的容器在初始化完成后使用相同凭据可成功执行查询。

## 根因与修复

- 根因：`mysqladmin ping` 只证明服务端有响应；即使认证失败，也不适合作为“凭据与目标数据库已可用”的门禁。
- 修复：循环使用目标 root 凭据执行 `SELECT 1`，退出码为 0 后才导入。
- 回归：MySQL dump 导入成功，`roles=2`、`users=2` 与备份基线一致。
