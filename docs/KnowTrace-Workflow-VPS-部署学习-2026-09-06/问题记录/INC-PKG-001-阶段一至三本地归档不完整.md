# INC-PKG-001：阶段一至三本地归档不完整

## 现象

原工作区保存了阶段一和阶段二的大部分文字记录，但阶段三本地目录只有摘要和后补的 ELK SOP。摘要曾指向一个不存在的桌面目录，VPS 脚本和可观测性配置没有完整落到本地。

## 影响

- 用户无法只依靠本地目录复习安装和配置；
- VPS 丢失时，服务器专用配置和原始演练日志可能无法从 Git 完整恢复；
- 旧 Ubuntu 实验目录中的同名文件与当前 VPS 版本不同，容易误用。

## 处理

1. 创建桌面目录 `KnowTrace-Workflow-VPS-部署学习-2026-09-06`；
2. 按阶段整理原有文档、证据和问题记录；
3. 从 VPS 白名单复制非敏感 Compose、脚本、配置、systemd 和演练日志；
4. 排除 `.env`、私钥、授权码、数据库归档和真实业务数据；
5. 对 40 份本地副本与 39 个唯一 VPS 源文件执行 SHA-256 比对，全部一致；
6. 增加 Mermaid 流程、当前状态和生产差距总结。

## 整理过程中的附带问题

首次批量复制原有文档时使用了 PowerShell `Copy-Item -LiteralPath` 加通配符。`-LiteralPath` 不展开 `*`，因此多个目录第一次未复制。随后改为：

```powershell
Get-ChildItem -LiteralPath <源目录> -File |
  Copy-Item -Destination <目标目录>
```

第一次失败没有删除或覆盖文件；修正后重新枚举目标目录，并使用哈希清单终验。

阶段三 SCP 批量调用超过一次 30 秒等待窗口，但后台复制已结束。没有盲目重试覆盖，而是先枚举目标文件，再进行 VPS/本地 SHA-256 全量比对，结果全部一致。

合并D盘旧包时，第一次生成映射 CSV 使用了函数内部的普通 `$records +=`。PowerShell 函数作用域创建了局部变量，文件复制成功但导出的映射表为空。处理方式是先枚举目标确认59份文件已落地，再使用脚本作用域的强类型 List 重建源/目标映射并逐项比较 SHA-256；没有重新复制或覆盖文件。

完成 D 盘复制与 146 份文件逐项校验后，原计划递归删除桌面副本，但本机安全策略在命令启动前拦截了该操作，未发生删除。随后采用可恢复方案：将桌面原件整体移动到 D 盘 `_archive`，再确认桌面原路径不存在、D 盘主版本与两份归档均存在。这样既完成迁移，也保留了回滚副本。
