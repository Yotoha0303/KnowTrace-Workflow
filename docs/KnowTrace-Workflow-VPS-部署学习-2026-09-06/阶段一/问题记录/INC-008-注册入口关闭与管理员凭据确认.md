# INC-008：注册入口关闭与管理员凭据确认

- 时间：2026-09-06
- 状态：已定位，未修改生产配置
- 影响：公网登录页可以访问，但用户无法自助注册；用户一度无法确认初始管理员是否已创建以及密码是否存在。
- 安全边界：本文只记录凭据是否配置，不保存管理员用户名、密码、Token、Cookie、私钥或完整 `.env`。

## 现象

1. `https://knowtrace.duckdns.org/login` 可以打开，但页面不显示“没有账号？创建账号”。
2. 访问 `/register` 后返回登录页，无法看到注册表单。
3. 用户无法从公开页面判断初始管理员账户和密码是否存在。

## 影响范围

- 已有账号仍可通过用户名和密码登录。
- 新用户不能自助创建账号。
- 应用、数据库和 HTTPS 未因此中断。

- 注册页面在开关关闭时会重定向到 `/login?registration=disabled`。

## 原因分析

### 已确认原因

注册入口没有丢失，也不是远程遗漏了登录页面。生产部署关闭了公开注册，前端因此隐藏注册链接，并把 `/register` 重定向回登录页。这与本地代码设计一致。

### 管理员账户判断

管理员账户、管理员角色、生产密码配置和数据库密码哈希均存在。当前证据不支持“管理员账户未创建”或“管理员密码不存在”的判断。

如果用户仍无法登录，应继续区分以下情况：

1. 用户不知道 VPS 中实际配置的管理员用户名或密码。
2. 输入的凭据与首次初始化时使用的凭据不同。
3. 后续曾修改密码，但本地记录没有保存新值。
4. 登录限流、Cookie 或浏览器状态导致登录失败。

不能通过公开页面展示管理员密码，也不能把密码补写到故障记录中。

## 处理建议

### 推荐方案：继续关闭公网注册

1. 通过 VPS 控制台或有效 SSH 会话读取管理员用户名；密码只在受控终端中处理。
2. 若无法确认原密码，走受控密码重置流程，不在聊天、Git 或学习文档中传播密码。
3. 登录成功后验证 `/api/v1/auth/session`、主页访问和管理员权限。
4. 后续增加“管理员创建用户”或邀请码机制，再考虑开放用户入口。

### 实验方案：临时开放注册

仅在明确接受公网注册风险时，把生产环境的 `AUTH_REGISTRATION_ENABLED` 调整为 `true`，重新创建 app/auth 服务，验证注册链接、注册接口和新账号登录；实验结束后恢复为 `false`。

## 验收标准

- 登录页显示正常且已有管理员可以成功登录。
- 明确记录注册策略是“关闭”“临时开放”还是“长期开放”。
- 若注册开启，登录页出现注册链接且 `/register` 显示注册表单。
- 若注册关闭，页面应明确提示联系管理员，而不是让用户误以为功能丢失。
- 管理员密码、Token、Cookie 和完整 `.env` 不进入 Git、日志、截图或故障记录。

## 回滚

如果临时开放注册后需要回滚：将 `AUTH_REGISTRATION_ENABLED` 恢复为 `false`，重新创建 app/auth 服务，再确认注册链接消失、已有管理员仍能登录。
