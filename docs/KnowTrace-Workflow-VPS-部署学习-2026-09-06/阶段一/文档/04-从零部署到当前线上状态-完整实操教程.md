# 从零部署到当前线上状态：完整实操教程

## 0. 这份教程解决什么问题

目标是在一台全新的 Ubuntu 24.04 VPS 上，把 KnowTrace-Workflow 部署成当前阶段一架构：

```text
公网浏览器
  -> Caddy :80/:443（自动 HTTPS、安全响应头、边缘访问日志）
  -> Nginx 127.0.0.1:8080（应用反向代理与第二层日志）
  -> Docker Compose app 127.0.0.1:3000
     -> PostgreSQL
     -> Go auth -> MySQL + Redis
```

完成后必须能回答：源码在哪里、容器在哪里、数据在哪里、秘密在哪里、日志在哪里、如何更新、故障时从哪一层开始查。

这是一台单 VPS 的真实部署学习，不是高可用生产集群。阶段一已经在 `knowtrace.duckdns.org` 验证过；本教程是事后整理的可复现版本，尚未在第二台空白 VPS 上完整重放。

## 1. 先认识四类位置

| 类型 | 位置 | 用途 | 能否删除 |
|---|---|---|---|
| Windows 源码 | `C:\Users\Yotoha\Desktop\KnowTrace-Workflow` | 本机开发与 Git 提交 | 不应删除 |
| VPS 源码 | `/opt/knowtrace` | 线上构建、Compose 与上传文件 | 不应随意删除 |
| 容器运行目录 | `/app` | 镜像内构建产物 | 容器重建后可变化 |
| 数据卷 | Docker 管理 | PostgreSQL、MySQL、Redis 数据 | 普通故障严禁删除 |
| 生产秘密 | `/opt/knowtrace/.env` | 密码、JWT、AI 服务端密钥 | 权限必须为 `600` |

源码没有挂载到 `app` 容器。修改 `/opt/knowtrace` 后必须重新构建镜像；直接进入容器修改 `/app`，容器重建后会丢失，也无法形成 Git 记录。

## 2. 部署前准备

### 2.1 需要准备的值

不要把下面的占位符原样执行：

```text
<VPS_IP>       VPS 公网 IPv4，例如 203.0.113.10
<SSH_PORT>     当前 SSH 端口，默认通常为 22
<DOMAIN>       域名，例如 knowtrace.duckdns.org
<SSH_KEY>      Windows 私钥路径
<TARGET_REF>   要部署的 Git 提交或标签
```

本机当前专用私钥路径：

```text
C:\Users\Yotoha\.ssh\knowtrace_vps_ed25519
```

私钥不上传到 Git、不复制进 VPS 项目、不写入故障记录。VPS 只保存对应公钥。

### 2.2 云厂商侧检查

先在云控制台确认：

- [ ] Ubuntu 24.04 64 位。
- [ ] 有控制台/VNC 救援入口，避免 SSH 加固失误后彻底失联。
- [ ] 安全组允许 `<SSH_PORT>/tcp`、`80/tcp`、`443/tcp`。
- [ ] 不开放 3000、8080、8082、15432、3306、6379 到公网。
- [ ] 域名 A 记录最终指向 `<VPS_IP>`。

## 3. 从 Windows 连接 VPS

在 PowerShell 中：

```powershell
$VpsIp = "<VPS_IP>"
$SshPort = <SSH_PORT>
$Key = "C:\Users\Yotoha\.ssh\knowtrace_vps_ed25519"

Test-NetConnection $VpsIp -Port $SshPort
ssh -p $SshPort -i $Key root@$VpsIp
```

第一次连接会显示主机指纹。应先从云厂商控制台核对指纹，确认后再接受，不要无条件忽略主机密钥警告。

连接后用以下命令认识当前环境：

```bash
whoami
hostnamectl
cat /etc/os-release
uname -a
pwd
ip -brief address
ip route
free -h
df -hT /
lsblk -f
timedatectl
```

验收：系统为 Ubuntu 24.04；磁盘、内存、默认路由和时间均合理。

## 4. 建立变更前证据

先创建只允许 root 查看和写入的运维目录：

```bash
install -d -m 0700 /root/knowtrace-ops/backups/before-install

cp -a /etc/ssh/sshd_config /root/knowtrace-ops/backups/before-install/
cp -a /etc/ufw /root/knowtrace-ops/backups/before-install/ufw
test -d /etc/nginx && cp -a /etc/nginx /root/knowtrace-ops/backups/before-install/nginx || true
test -d /etc/caddy && cp -a /etc/caddy /root/knowtrace-ops/backups/before-install/caddy || true

systemctl --failed --no-pager
```

这里的 `test ... && ... || true` 表示：目录存在才备份；不存在不让整段检查中断。

## 5. 系统更新和常用工具

这些命令会安装软件并可能带来新的内核。不要在未知业务高峰直接重启：

```bash
apt update
apt upgrade -y
apt install -y ca-certificates curl git jq openssl dnsutils ufw nginx

git --version
curl --version | head -n 1

```

检查是否需要重启：

```bash
test -f /var/run/reboot-required && cat /var/run/reboot-required || echo "no reboot required"
```

如果需要重启，先完成 SSH 密钥验证并选择维护窗口。重启后重新运行第 3 节的系统盘点。

## 6. UFW 防火墙

### 6.1 先放行当前 SSH 端口

错误顺序会把自己锁在服务器外。先在另一窗口保持现有 SSH 会话：

```bash
ufw status verbose
ufw default deny incoming
ufw default allow outgoing
ufw allow <SSH_PORT>/tcp comment 'SSH key access'
ufw allow 80/tcp comment 'Caddy HTTP and ACME'
ufw allow 443/tcp comment 'Caddy HTTPS'
ufw enable
ufw status numbered
```

然后从第二个 PowerShell 窗口重新 SSH 登录。第二连接成功前，不要关闭原连接，也不要关闭密码登录。

注意：Docker 发布的端口可能绕过部分 UFW 规则。因此本项目依靠 Compose 把应用和数据库端口绑定到 `127.0.0.1`，而不是只依赖 UFW。

### 6.2 验收

```bash
ss -lntup
ufw status verbose
```

公网只应需要 SSH、80、443。3000、8080、8082、15432 如果监听，必须只监听 `127.0.0.1`。

## 7. SSH 密钥加固

把 Windows 公钥安装到服务器。推荐先使用 `scp` 发送公钥文件，再在服务器设置权限：

```powershell
scp -P <SSH_PORT> -i "C:\Users\Yotoha\.ssh\knowtrace_vps_ed25519" `
  "C:\Users\Yotoha\.ssh\knowtrace_vps_ed25519.pub" `
  root@<VPS_IP>:/root/knowtrace_vps_ed25519.pub
```

VPS 中：

```bash
install -d -m 0700 /root/.ssh
touch /root/.ssh/authorized_keys
chmod 0600 /root/.ssh/authorized_keys
grep -qxF "$(cat /root/knowtrace_vps_ed25519.pub)" /root/.ssh/authorized_keys \
  || cat /root/knowtrace_vps_ed25519.pub >> /root/.ssh/authorized_keys
rm /root/knowtrace_vps_ed25519.pub
```

先在新窗口确认密钥登录成功，再创建 `/etc/ssh/sshd_config.d/00-knowtrace-hardening.conf`：

可以从 Windows 上传本目录中的配置样例：

```powershell
scp -P <SSH_PORT> -i "C:\Users\Yotoha\.ssh\knowtrace_vps_ed25519" `
  "C:\Users\Yotoha\Desktop\KnowTrace-Workflow-VPS-部署学习-2026-09-06\配置样例\00-knowtrace-hardening.conf" `
  root@<VPS_IP>:/root/00-knowtrace-hardening.conf
```

VPS 中先阅读并安装：

```bash
sed -n '1,120p' /root/00-knowtrace-hardening.conf
install -o root -g root -m 0644 /root/00-knowtrace-hardening.conf \
  /etc/ssh/sshd_config.d/00-knowtrace-hardening.conf
```

文件内容为：

```text
PubkeyAuthentication yes
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin prohibit-password
MaxAuthTries 3
```

应用前检查：

```bash
sshd -t
sshd -T | grep -E '^(port|pubkeyauthentication|passwordauthentication|kbdinteractiveauthentication|permitrootlogin|maxauthtries) '
systemctl reload ssh
systemctl status ssh --no-pager
```

回滚只能通过仍打开的有效会话或云控制台完成：删除该 drop-in，执行 `sshd -t && systemctl reload ssh`。

## 8. 安装 Docker Engine 和 Compose

以下是 Docker 官方 Ubuntu apt 仓库方式，不使用 `get.docker.com` 远程安装脚本：

```bash
apt update
apt install -y ca-certificates curl
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc

cat >/etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF

apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
systemctl enable --now docker
docker version
docker compose version
docker run --rm hello-world
```

验收不仅是命令存在，还包括 daemon active 和容器能拉取、运行、正常退出：

```bash
systemctl is-active docker
docker info --format 'driver={{.Driver}} logging={{.LoggingDriver}}'
```

## 10. 生成生产环境变量

从 Windows 上传本目录的 `配置样例/init-env.sh`：

```powershell
scp -P <SSH_PORT> -i "C:\Users\Yotoha\.ssh\knowtrace_vps_ed25519" `
  "C:\Users\Yotoha\Desktop\KnowTrace-Workflow-VPS-部署学习-2026-09-06\配置样例\init-env.sh" `
  root@<VPS_IP>:/root/init-env.sh
```

VPS 中先阅读，再执行：

```bash
sed -n '1,240p' /root/init-env.sh
install -m 0750 /root/init-env.sh /usr/local/sbin/knowtrace-init-env
/usr/local/sbin/knowtrace-init-env /opt/knowtrace/.env
```

预期权限为 `600`。不要运行 `cat .env`，不要把 `docker compose config` 的完整输出贴进聊天或日志。

首次登录密码由脚本随机生成。仅在自己的终端临时查看：

```bash
grep '^KNOWTRACE_ADMIN_USERNAME=' /opt/knowtrace/.env
grep '^KNOWTRACE_ADMIN_PASSWORD=' /opt/knowtrace/.env
```

首次登录后立即修改密码。修改后 `.env` 中的初始化密码不会自动同步，也不再代表当前密码。

## 11. 添加生产 Compose 覆盖文件

在 Windows 上传 `配置样例/compose.production.yaml`：

```powershell
scp -P <SSH_PORT> -i "C:\Users\Yotoha\.ssh\knowtrace_vps_ed25519" `
  "C:\Users\Yotoha\Desktop\KnowTrace-Workflow-VPS-部署学习-2026-09-06\配置样例\compose.production.yaml" `
  root@<VPS_IP>:/opt/knowtrace/compose.production.yaml
```

然后在 VPS 校验：

```bash
cd /opt/knowtrace
chmod 0644 compose.production.yaml
docker compose -f compose.yaml -f compose.production.yaml config --quiet
```

`config --quiet` 只做校验，不打印插值后的秘密。生产覆盖文件限制 Docker JSON 日志为单文件 10 MiB、保留 5 个文件。

首次启动前创建外部卷：

```bash
docker volume create go-user-system_mysql_data
docker volume create go-user-system_redis_data
docker volume ls | grep -E 'knowtrace|go-user-system'
```

PostgreSQL 卷由 Compose 自动创建。不要为普通更新删除任何卷。

## 12. 构建和启动容器

2 GB 内存机器首次构建可能使用 Swap，需耐心观察：

```bash
cd /opt/knowtrace
docker compose -f compose.yaml -f compose.production.yaml up -d --build --wait
docker compose -f compose.yaml -f compose.production.yaml ps -a
```

应看到：

- `app`、`auth`、`postgres`、`auth-mysql`、`auth-redis` 为 running/healthy。
- `auth-migrate`、`auth-bootstrap` 为 exited (0)，它们是一次性任务，不应强行保持 running。

失败时先看日志，不要反复重启：

```bash
docker compose -f compose.yaml -f compose.production.yaml logs --tail=200 app
docker compose -f compose.yaml -f compose.production.yaml logs --tail=200 auth auth-migrate auth-bootstrap
docker compose -f compose.yaml -f compose.production.yaml logs --tail=200 postgres auth-mysql auth-redis
free -h
df -hT /
```

## 13. 应用直连验收

```bash
curl -fsS http://127.0.0.1:3000/api/health/live
curl -fsS http://127.0.0.1:3000/api/health/ready
curl -fsS http://127.0.0.1:8082/livez
curl -fsS http://127.0.0.1:8082/readyz
```

解释：

- live 成功：进程活着。
- ready 成功：服务及关键依赖可工作。
- live 成功、ready 失败：优先检查数据库或依赖，而不是直接宣布整个进程宕机。

检查端口绑定：

```bash
ss -lntp | grep -E ':(3000|8082|15432)\b'
```

这些端口必须显示 `127.0.0.1`，不能是 `0.0.0.0`。

## 15. DNS 验证

在启动 Caddy 自动签证书前，至少从两个 DNS 视角确认域名：

```bash
dig +short <DOMAIN> A
dig @1.1.1.1 +short <DOMAIN> A
dig @8.8.8.8 +short <DOMAIN> A
```

结果都应为 `<VPS_IP>`。如果仍是旧 IP，先等待或修正 DNS；不要靠反复重启 Caddy解决。

## 16. 安装 Caddy

使用 Caddy 官方稳定 apt 仓库：

```bash
apt install -y debian-keyring debian-archive-keyring apt-transport-https curl gnupg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' \
  | gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' \
  | tee /etc/apt/sources.list.d/caddy-stable.list
chmod o+r /usr/share/keyrings/caddy-stable-archive-keyring.gpg
chmod o+r /etc/apt/sources.list.d/caddy-stable.list
apt update
apt install -y caddy
caddy version
systemctl status caddy --no-pager
```

官方包会创建 `caddy` 用户和 systemd 服务。服务进程不是 root，因此写文件前必须考虑目录权限。

## 17. 配置 Caddy HTTPS

先准备日志目录，不要预先创建一个 root:root、600 的日志文件：

```bash
install -d -o caddy -g caddy -m 0750 /var/log/caddy
test ! -e /var/log/caddy/knowtrace-access.log \
  || chown caddy:caddy /var/log/caddy/knowtrace-access.log
```

从 Windows 上传本目录 `配置样例/Caddyfile`：

```powershell
scp -P <SSH_PORT> -i "C:\Users\Yotoha\.ssh\knowtrace_vps_ed25519" `
  "C:\Users\Yotoha\Desktop\KnowTrace-Workflow-VPS-部署学习-2026-09-06\配置样例\Caddyfile" `
  root@<VPS_IP>:/root/Caddyfile
```

VPS 中先阅读、备份并安装：

```bash
sed -n '1,200p' /root/Caddyfile
cp -a /etc/caddy/Caddyfile /root/knowtrace-ops/backups/before-install/Caddyfile.package-default
install -o root -g caddy -m 0640 /root/Caddyfile /etc/caddy/Caddyfile

caddy fmt --overwrite /etc/caddy/Caddyfile
sudo -u caddy caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
systemctl reload caddy
systemctl status caddy --no-pager
journalctl -u caddy -n 100 --no-pager
```

Caddy 识别到公网域名后会自动申请并续期证书，同时把 HTTP 重定向到 HTTPS。必要条件是 DNS 正确、80/443 可从公网访问、Caddy 能写持久化数据目录。

## 18. 全链路验收

### 18.1 VPS 本机

```bash
curl -sS -o /dev/null -w 'nginx=%{http_code}\n' http://127.0.0.1:8080/api/health/ready
curl -sS -o /dev/null -w 'http=%{http_code} redirect=%{redirect_url}\n' http://<DOMAIN>/login

```

### 18.2 证书

```bash
echo | openssl s_client -connect <DOMAIN>:443 -servername <DOMAIN> 2>/dev/null \
  | openssl x509 -noout -subject -issuer -dates
```

### 18.3 Windows 外部视角

```powershell
Resolve-DnsName <DOMAIN>
curl.exe -I http://<DOMAIN>/login
curl.exe -I https://<DOMAIN>/login
```

最终验收：HTTP 跳转 HTTPS；证书域名匹配；登录页和 live/ready 返回 2xx；Docker、Nginx、Caddy 三层日志都能读取。

## 19. 日志在哪里

```bash
cd /opt/knowtrace

# 容器日志
docker compose -f compose.yaml -f compose.production.yaml logs --since=30m app auth
docker compose -f compose.yaml -f compose.production.yaml logs -f app

# Nginx
tail -n 100 /var/log/nginx/knowtrace.access.log
```

`docker compose logs` 是首选，不要直接编辑 `/var/lib/docker/containers` 下的内部日志文件。

## 20. 安全更新流程

```bash
cd /opt/knowtrace
git status --short --branch
git rev-parse HEAD

git log --oneline --decorate --max-count=10 HEAD..origin/main
```

确定更新后：

```bash
git merge --ff-only <TARGET_REF>
```

## 21. 停止、恢复和禁止事项

安全停止且保留数据卷：

```bash
cd /opt/knowtrace
docker compose -f compose.yaml -f compose.production.yaml down
```

恢复启动：

```bash
docker compose -f compose.yaml -f compose.production.yaml up -d --wait
```

禁止在普通故障中执行：

```text
docker compose down --volumes
docker volume prune
git reset --hard
rm -rf /opt/knowtrace
```

这些操作可能删除数据或覆盖未确认的修改。恢复不是“容器启动了”，而是 ready 成功、关键业务记录可读、登录和保存链路正常。

## 22. 故障排查顺序

按用户请求路径从外向内：

```text
DNS -> 80/443 -> Caddy -> Nginx -> app -> PostgreSQL/auth -> MySQL/Redis
```

### 域名打不开

```bash
dig +short <DOMAIN> A
ufw status numbered
ss -lntp | grep -E ':(80|443)\b'
systemctl status caddy --no-pager
journalctl -u caddy -n 100 --no-pager
```

### HTTPS 正常但返回 502

```bash
curl -v http://127.0.0.1:8080/api/health/ready
nginx -t
tail -n 100 /var/log/nginx/knowtrace.error.log
curl -v http://127.0.0.1:3000/api/health/ready
docker compose -f /opt/knowtrace/compose.yaml -f /opt/knowtrace/compose.production.yaml ps -a
```

### 页面说“数据库未启动”

先用证据判断，不相信通用错误文案：

```bash
curl -i http://127.0.0.1:3000/api/health/live
curl -i http://127.0.0.1:3000/api/health/ready
docker compose -f /opt/knowtrace/compose.yaml -f /opt/knowtrace/compose.production.yaml logs --since=15m app postgres auth
```

当前已知缺陷：登录会话过期也可能被全局错误页误报为数据库故障。

## 23. 每次练习必须保存的证据

使用以下模板：

```markdown
目标：
环境与目标提交：
变更前状态：
执行命令：
实际输出摘要：
验收结果：
故障现象：
根因证据：
恢复操作：
恢复后业务验证：
残留风险：
```

不要记录密码、Token、Cookie、私钥、完整 `.env`、真实业务内容或未经脱敏的访问日志。
