# 常用命令与回滚

## 日常状态检查

```bash
cd /opt/knowtrace
docker compose -f compose.yaml -f compose.production.yaml ps -a
docker compose -f compose.yaml -f compose.production.yaml logs --tail=100 app auth
curl -fsS http://127.0.0.1:3000/api/health/live
curl -fsS http://127.0.0.1:3000/api/health/ready
curl -fsS http://127.0.0.1:8080/nginx-health
systemctl status nginx caddy docker --no-pager
journalctl -u caddy -n 100 --no-pager
tail -n 100 /var/log/nginx/knowtrace.error.log
tail -n 100 /var/log/nginx/knowtrace.access.log
tail -n 100 /var/log/caddy/knowtrace-access.log
```

## 发布与更新（先确认目标提交）

```bash
cd /opt/knowtrace
git status --short --branch
git rev-parse HEAD
git fetch --prune origin
# 确认目标提交后再执行 git pull --ff-only
docker compose -f compose.yaml -f compose.production.yaml up -d --build --wait
```

不要直接使用会覆盖工作树的 `git reset --hard`，也不要在未备份和未做恢复演练前删除数据卷。

## 安全停止（保留数据卷）

```bash
cd /opt/knowtrace
docker compose -f compose.yaml -f compose.production.yaml down
```

不要在普通故障处理中添加 `--volumes`，它会删除数据库卷。

## 入口回滚

```bash
systemctl stop caddy
cp -a /root/knowtrace-ops/backups/pre-stage1-20260906/sites-available/default /etc/nginx/sites-available/default
ln -sfn /etc/nginx/sites-available/default /etc/nginx/sites-enabled/default
rm -f /etc/nginx/sites-enabled/knowtrace.conf
nginx -t && systemctl restart nginx
```

## SSH 回滚（只能通过仍有效的密钥会话或 VPS 控制台执行）

```bash
rm -f /etc/ssh/sshd_config.d/00-knowtrace-hardening.conf
sshd -t && systemctl reload ssh
```

## 重要路径

- 应用：`/opt/knowtrace`
- 秘密：`/opt/knowtrace/.env`（`600`，禁止复制到文档/Git）
- 入口配置：`/etc/caddy/Caddyfile`、`/etc/nginx/sites-available/knowtrace.conf`
- 配置备份：`/root/knowtrace-ops/backups/pre-stage1-20260906`
- 上传文件：`/opt/knowtrace/data/uploads`
- Caddy 日志：`/var/log/caddy/knowtrace-access.log`
- Nginx 日志：`/var/log/nginx/knowtrace.access.log`、`/var/log/nginx/knowtrace.error.log`
