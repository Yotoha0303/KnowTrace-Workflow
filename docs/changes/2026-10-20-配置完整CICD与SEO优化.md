## 2. 依据与背景

1. **生产健康巡检与 Render 实例保活**：
   - 生产环境前端已部署于 Vercel（`https://knowtrace-workflow.vercel.app`），Go 认证后端已部署于 Render（`https://go-user-system.onrender.com`）。
   - Render 免费实例在无流量 15 分钟后会自动进入休眠状态（Spin down），再次唤醒存在冷启动延迟。
   - 配置每 12 小时（`0 */12 * * *`）定时探针巡检，不仅能防止服务长期僵死或冷启动失败，更能建立生产环境可用性的持续观测基线。
2. **SEO 搜索引擎与社交分享全链路优化**：
   - 动态 `robots.ts` 与 `sitemap.ts` 提供开箱即用的标准搜索引擎抓取索引；
   - `layout.tsx` 配置标准的 OpenGraph 与 Twitter Card 标签，在主流开发者社交平台与即时通讯软件中展现精美卡片预览；
   - `README.md` 是项目的第一门面。添加技术栈徽标（Badges）与醒目的在线 Demo 链接能大幅降低评估者的体验门槛；
   - 补充 SEO 核心关键词（如 Knowledge Base, Evidence Tracing, Verifiable Publishing, Next.js 16, Go Microservice, SRE Observability）增强被发现性；
   - 梳理双轨部署拓扑：既体现云原生全栈（Vercel + Render + Supabase）的现代 SaaS 交付形态，又保留原有一台 2 vCPU 规格 VPS 极简全栈（Caddy + Nginx + Docker Compose + PLG 监控栈）的自托管韧性。
3. **运维台账状态对齐**：
   - PR #55 已完成 M4 阶段 compose 切库与认证服务切换 PostgreSQL 18，`auth-e2e-repeat.yml` 已经将 MySQL 替换为 PostgreSQL 18，`KT-DEFER-014`（Issue #52）已实质闭环。
