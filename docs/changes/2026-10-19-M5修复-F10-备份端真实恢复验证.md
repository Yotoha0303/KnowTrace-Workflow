# 2026-10-19 · M5 修复 F10 · 备份端加真实恢复验证（结构判据降级为快速失败）

> 依据：CI run `39258948661`（PG **18**）的 `Backup dump criteria on PostgreSQL 18` job
> 报 `N3/full --file=/dev/null rejects data flip expected=1 actual=0`。
> 即：**全量 `pg_restore --file=/dev/null` 在 PG 18 上对数据区翻字节返回 0**，
> 而此前在 PG 17.11 上实测为 1 —— **该判据不跨版本成立**。
>
> 处置方向：**不**下调 CI 期望值（那是降低判据），而是把备份端的「完整性」从
> 「结构/解压判据」升级为「**真实恢复 + 逐表计数逐字节比对**」。

---

## 1. 改了什么（提交 1：`scripts/linux/backup-all.sh`）

| 位置 | 变更 |
| --- | --- |
| 新增 `verify_temp_databases` + `drop_verify_databases` | 本次备份创建的临时验证库记账；删除前**校验库名带本次 `nonce`**，不符则拒删并告警 |
| 新增 `verify_dump_by_real_restore` | `createdb` → `pg_restore --exit-on-error --no-owner --no-privileges` → 同一段 `emit_pg_table_counts_sql` → 与 `*-counts.tsv` 逐字节 `cmp` → `dropdb`；**恢复库计数为空**也 die（空分母不得判绿） |
| `on_exit` | 先 `drop_verify_databases`，再 `restore_runtime`；新增 `SIGTERM`/`SIGINT` trap 走同一条 EXIT 清理路径 |
| 主应用 / 认证库段 | dump 后、**落归档前**各调一次 `verify_dump_by_real_restore`；失败即 `die` |
| 结构判据注释 | 改为「**快速失败前置，不是完整性证据**」，并记录 PG 18 的逐条实测（见 §2） |
| 依赖 | `require_command` 增加 `cmp diff` |
| 新增环境变量 | `POSTGRES_VERIFY_USER`（默认 `knowtrace_workflow`）、`AUTH_POSTGRES_VERIFY_USER`（默认 `$AUTH_POSTGRES_USER`） |

### 权限要求（已写进脚本头部注释）

真实恢复要在**目标实例上建临时库再删**，故执行用户必须有 `CREATEDB`：

- 主应用：compose 的 `POSTGRES_USER` 就是 `knowtrace_workflow`（实例超级用户），默认即可；
- 认证库：M4 切库后的管理用户是 `auth_admin`，应用用户 `go_user_system` 可能只有 LOGIN/CONNECT。
  生产若如此，须设 `AUTH_POSTGRES_VERIFY_USER=auth_admin`。
- **两者都没有 CREATEDB ⇒ 备份失败**。这是有意的：宁可备份失败，也不落一份没经过真实恢复验证的归档。

## 2. 为什么结构判据不再是证据（CI 实测，逐条）

CI run `39258948661`（PG 18）的四条路径实测：

| 注入 | `--list` | `--data-only` | 全量 `--file=/dev/null` | 末 5 字节 | 真实恢复 |
| --- | --- | --- | --- | --- | --- |
| append-128B | 0 | 0 | 0 | **1** | —（唯一拦截者是末 5 字节） |
| truncate-128B | 0 | **1** | **1** | 1 | — |
| 数据区翻 1 字节 | 0 | 0 | **0（PG 17.11 上为 1）** | 0 | **必须 1**（本判据） |
| 空库 dump | 0 | — | — | 0 | 由「逐表计数为空」拦（N4c） |

⇒ 结构判据保留只为**快**（解压前即可拦），完整性证据只有真实恢复。
