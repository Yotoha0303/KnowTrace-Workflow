## 2. 依据与背景

1. **故障背景**：
   - 用户反馈“在生产环境可以正常注册账号，但无论使用已有账号还是新注册账号均无法登录”。
   - 经实测抓取网络流发现：Go 认证后端与 Next.js 登录路由均正确返回 200 并下发 Cookie，但随后浏览器访问受保护页面 `/` 时，Next.js 服务端崩溃并抛出 **500 Internal Server Error**，导致客户端路由跳转被拦截中断，停留在登录页。
2. **根因定位**：
   - 架构设计（`0020_workspace_foundation.sql` 与 `src/shared/workspace.ts`）规定了硬编码默认空间锚点 `00000000-0000-4000-8000-000000000001`。
   - 此前运行的演示数据清理脚本无差别执行了 `DELETE FROM workspaces`，抹除了该锚点；
   - 导致后续所有用户在登录后访问工作区时，Next.js 调用的 `ensureLegacyWorkspaceMembership` 触发 PostgreSQL 外键违约约束，引发 500 级崩溃。

## 3. 验收标准（可判定）

1. **默认空间就绪**：数据库 `workspaces` 表中存在 ID 为 `00000000-0000-4000-8000-000000000001` 的记录。
2. **外键约束不违约**：执行插入 `workspace_memberships` 动作无报错，返回成功。
3. **已认证首页 200 OK**：携带 Session Cookie 访问 `GET https://knowtrace-workflow.vercel.app/` 返回 **200 OK**（非 500，非 307），HTML 包含完整的个人仪表盘与用户信息。
4. **全链路端到端自动化验证**：新用户从注册、登录、换取 Token、设置 Cookie 到访问首页的全生命周期流程 100% 畅通通过。
