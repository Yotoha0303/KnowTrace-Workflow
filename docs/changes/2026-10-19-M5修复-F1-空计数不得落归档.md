# 2026-10-19 · M5 修复 F1 · 空逐表计数不得落归档

> 依据：M5 三跳链阻断项 **F1**（独立验证方实测，缺陷编号 G-2 / A4）。
> 前置：`docs/changes/2026-10-19-运维链迁PostgreSQL-备份端.md`（备份端迁 PG）。

## 1. 缺陷

`scripts/linux/backup-all.sh` 的 `postgres_counts()` / `auth_postgres_counts()` 是
`psql | sed | sort > 文件` 的管道。管道里 `sed` / `sort` 的退出码是**最后一条命令**的，
`psql` 失败（或返回 0 行）时管道仍可能 `exit 0`，于是 **0 字节的 `*-counts.tsv` 照常落进归档**。

后果：`verify-restore.sh` 拿这份空清单与恢复库逐字节 `cmp`——
**空 vs 空也是相等**，恢复演练照样 `PASS`。这正是本项目反复踩过的「空分母判绿」。

## 2. 改动

`postgres_counts` / `auth_postgres_counts` 的输出写盘后立即判非空（`[[ -s ... ]]`），
为空即 `die`；两库都做。并在 `-counts.tsv` 上保留 `[[ -s ]]` 之外的**行数下限 1**语义
（`-s` 只挡 0 字节，空行会被 `sed` 删掉后仍可能是 0 字节，已覆盖）。

## 3. 验收（可执行）

| 用例 | 做法 | 期望 |
| --- | --- | --- |
| 负向（必须拦） | 桩掉 `psql`，使其输出空 | 脚本 `exit 1`，`BACKUP_ROOT` 下**不产生** `knowtrace-*.tar.gz`，`.incomplete-*` 保留 |
| 正向（不得误伤） | 正常库 | 两个 `*-counts.tsv` 非空，脚本继续往下走 |

## 4. 回滚

单文件回滚：`git revert <本提交>`。

## 5. 边界

只加「空即失败」判据；不改变计数 SQL 与归档结构。
