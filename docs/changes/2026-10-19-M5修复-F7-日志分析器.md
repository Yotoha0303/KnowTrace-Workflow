## 1. `--samples` 被文案引用但不存在

`--samples` 在报告里被点两次（原 `:549` 与 `:621`：「原始行见 --samples」），
但 `argparse` 里**没有这个参数**——照着提示敲会得到 `unrecognized arguments`。

**实现**（选择「实现」而不是「删文案」：归一化后的模式串刻意不含原始值，
没有样本行就无法判断上下文）：

- 新增 `--samples N`（默认 0 = 不打印）；
- `PatternStat` 增加 `samples: list[str]`，每模式最多存 5 条（`_MAX_SAMPLES`）；
- **存的是 `redact_line(raw)` 的产物**，打印时不再二次加工 —— 与报告其余部分同一套脱敏规则。

## 2. 空分母判绿

原实现：零容器时 `lines_total == 0`、`all_stats` 为空，于是依次打印
`log.patterns=OK` / `log.error-volume=OK` / `log.conclusion=OK（未发现错误模式）`，**退出码 0**。
**什么都没解析到，却报告一切正常**——与本仓库反复踩到的「空分母 100%」同族。

**改动**（区分「没东西可看」与「看了且干净」）：

| 情形 | 结果 |
| --- | --- |
| 零来源（一个容器/文件都没解析到） | **FAIL** `log.sources`：没有输入，结论不可用 |
| 有来源但读到 0 行 | **WARN**：`log.sources` / `log.patterns` / `log.high-risk` / `log.error-volume` / `log.conclusion` 五条都写明「没有分母」 |
| 读到行、无 error/warn | OK（不变） |

## 3. 脱敏漏形（逐条修复前后对照，均实测）

| 输入 | 修复前（HEAD） | 修复后 |
| --- | --- | --- |
| `postgres_password="abc def"` | `postgres_password=*** def"` ← **残留** | `postgres_password=***` |
| `postgres://u:p@ss@h/db` | `postgres://***:***@ss@h/db` ← **残留半段** | `postgres://***:***@h/db` |
| `postgres://u:p/w@h/db` | `postgres://u:p/w@h/db` ← **原文未改** | `postgres://***:***@h/db` |
| `PGPASSFILE=/root/.pgpass:S3cretPass` | `PGPASSFILE=/root/.pgpass:S3cretPass` ← **未脱敏** | `PGPASSFILE=***` |
| `password=plain-secret host=db` | `password=*** host=db` | 同左（无回归） |
| `Authorization: Bearer eyJ…` | `Authorization=*** eyJ…` ← **token 残留** | `Authorization=*** ***` |
| `http://host:8080/path@x`（无凭据） | 原样 | **原样（不误伤）** |

修法：
- **键值**：值改为「带引号优先、否则非空白」`(?:"[^"]*"|'[^']*'|\S+)` —— 引号内的空格一并吃掉；
  键名表新增 `pgpassfile`（尾段是口令，整值替换）。
- **URL**：user 不含 `:/@`，口令**贪婪吃到最后一个 `@`**，且 `@` 后必须紧跟主机字符。
  http(s) 单独收紧为「口令不含 `/`」（RFC 3986 里 userinfo 的 `/` 必须百分号编码）——
  否则 `http://host:8080/path@x` 会被误脱敏（实测）。
- **独立 Bearer/Basic**：键值规则抓不到「只有前缀词、没有键」的形态，单列一条规则。

## 5. 边界

- 本机无 Docker：`docker` 用编译出来的 `docker.exe` 桩（只实现 `docker logs`，从文件回放日志）；
  `docker compose ps -q` 那一路在桩下返回空 ⇒ 恰好覆盖「零来源」分支。
- 真实 `docker logs --since/--tail` 的语义（窗口与截断）**未在本机验证**。
- 基线文件、JSON/Markdown 输出路径按 Windows 语义落在 `\var\lib\...`（本机无该目录），不影响判据。
