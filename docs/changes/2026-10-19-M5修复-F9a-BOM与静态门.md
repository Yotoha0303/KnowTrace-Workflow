# 2026-10-19 · F9a：修 `run-criteria.sh` 的 BOM，并给静态门补一条能抓它的判据

## 1. 现象（实测）

`tests/ci/pg-dump-criteria/run-criteria.sh` 以 **UTF-8 BOM**（`EF BB BF`）开头：

```text
$ head -c 3 tests/ci/pg-dump-criteria/run-criteria.sh | od -An -tx1
 ef bb bf
```

**它通过了当时的全部既有判据**：`bash -n` exit 0、`run-criteria.sh self-check` exit 0。
本机（Windows + Git Bash）也跑得动。

## 2. 为什么必须修（失效形态）

Linux 内核只把文件头 `#!` 当成 shebang。前面多 3 个字节后，
直接执行会报 `cannot execute: required file not found`——**`ci.yml` 正是用 `./run-criteria.sh` 直接调用它**。
即：本地全绿、CI 全红，而且报错文案与「文件不存在」同形，容易误判。

## 3. 修法

| 项 | 改动 |
| --- | --- |
| `tests/ci/pg-dump-criteria/run-criteria.sh` | 去掉开头 3 字节 BOM（**内容其余部分一字未动**） |
| `tests/ci/static-script-gate.ps1` | 每个 `.sh` 在 `bash -n` 之后**追加一条字节判据**：前 3 字节不得为 `EF BB BF` |

## 4. 正向

```text
== 汇总: 受检 52 个文件，失败 0 个 ==
STATIC_SCRIPT_GATE=PASS
```

## 5. 负向（必须有，否则等于没加）

把 BOM 重新注入 `run-criteria.sh`：

```text
FAIL .../tests/ci/pg-dump-criteria/run-criteria.sh (带 UTF-8 BOM：Linux 上 shebang 失效，bash -n 看不见)
== 汇总: 受检 52 个文件，失败 1 个 ==
STATIC_SCRIPT_GATE=FAIL
```

还原后重新 `PASS`。**注**：本机 `powershell -File` 的退出码经管道会被吞（上面 `exit=0` 是 `grep` 的），
CI 里是直接调用、不看管道——这一点在 §6 如实记。

## 6. 边界（如实）

- 本机无法在 Linux 上复现「`./run-criteria.sh` 报 required file not found」——
  **判据来自首字节的确定性事实，不是来自对该报错的本地复现**。
- 同一判定**没有**扩展到 `.py`（Python 允许 BOM）与 `.ps1`（Windows 侧接受 BOM）。只约束 `.sh`。
