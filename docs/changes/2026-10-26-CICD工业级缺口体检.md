### 2.1 最危险：判据存在，但位置让它永远不生效

#### N-1 `services/go-user-system/.github/workflows/` 下 3 个 workflow 从不执行

**【实测】**

```
$ git ls-files | grep '\.github/workflows/'
.github/workflows/auth-e2e-repeat.yml
.github/workflows/ci.yml
.github/workflows/production-health-check.yml
services/go-user-system/.github/workflows/ci.yml        ← 从不执行
services/go-user-system/.github/workflows/codeql.yml    ← 从不执行
services/go-user-system/.github/workflows/release.yml   ← 从不执行

$ gh api repos/Yotoha0303/KnowTrace-Workflow/actions/workflows --jq '.workflows[].path'

.github/workflows/ci.yml
.github/workflows/production-health-check.yml
dynamic/dependabot/dependabot-updates
dynamic/dependabot/update-graph
```

**只有 3 个真 workflow 注册在案。** GitHub 只执行**仓库根目录**的 `.github/workflows/`。

| 嵌套文件 | 本该做什么 | 现在 |
| --- | --- | --- |
| `codeql.yml` | CodeQL 静态分析（push + PR + 每周一 cron） | **0 次扫描** |
| `release.yml` | `push: tags: ["v*"]` → 构建推 `ghcr.io` | **从未跑过**；且仓库无任何 tag，即使执行也永不触发 |
| `ci.yml` | **`go test -race ./...`**（`:51`） | **从未跑过** ⇒ **全仓没有任何地方跑竞态检测** |

**为什么它不响**：文件内容看着正常；GitHub Security 页显示 Code scanning「未配置」，
那只是**空**，不是**失败**。⇒ **「我配了 CodeQL」与「CodeQL 在跑」在观测上不可分。**

同族先例（`AGENTS.md` §8）：`logrotate` 缺 `su`、`fail2ban` 单元名错配——**退出码都是 0**。

#### N-2 `production-health-check.yml` 每 12h 探活，但失败即静默

**【实测】** `git grep -n 'secrets\.' -- .github/workflows/` → **无输出**。
三个 workflow 一次都没引用过 `secrets.`；该 workflow 是 `permissions: contents: read`，
**连开 issue 的权限都没有**。

失败传播路径：**GitHub → Actions 红色 X → 没人看**。

对照 §2 **06 观测环**准出（Alertmanager active 区分 + 严重度参与 + 真实停机演练）：
**站点内部的观测链比这条外部探针还完整**（`deploy/monitoring/` 有告警规则、有每日
`alert-drill.timer`）。而外部探针是唯一能发现「整站全挂」的那个——**价值最高，告警链最弱**。

> ⚠️ **D3**：该 workflow 历史运行全部 success。**一个从未红过的告警，与一个永远不响的告警，
> 在观测上同形。**
