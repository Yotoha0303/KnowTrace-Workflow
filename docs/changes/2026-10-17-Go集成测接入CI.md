## 2. 依据（已实测，非推断）

| 事实 | 出处 |
| --- | --- |
| `go` job 只有 `go test ./...` 一步，未配 `TEST_DATABASE_DSN` | `ci.yml`（改前 `:118-123`） |
| 未配 ⇒ 集成测 `t.Skipf` | `internal/testutil/mysql.go:89-92` |
| 集成测试文件 2 个 / 集成用例 5 条 | `internal/dao/user_integration_test.go`（3）· `internal/service/auth_integration_test.go`（2） |
| `testutil` 用 `gorm.io/driver/mysql`（`mysql.Open`） | `internal/testutil/mysql.go:80-84` |
| `testutil` 拒绝库名不含 `test` 的库 | `internal/testutil/mysql.go:196-207` |
| `pkg/database` 的 DSN 形态 | `pkg/database/db.go:47-53` |
| e2e job 已有可照抄的 `mysql:8.0` service | `ci.yml:202-215` |

**为什么这条门必须存在**：`ADR-0019` §5.6 的每条负向判据（方言残留、`GET_LOCK` 语义、
排序规则差异）都要求「改错数据层能被发现」。测试被 skip 时，CI 全绿**不携带任何信息**——
这正是「看起来在测、其实没测到」的形态（`AGENTS.md` §4.2）。

## 3. 改动方案

1. `go` job 增 `services.mysql`：照抄 e2e job 的 `mysql:8.0` 形态（同一镜像、同一套
   env 键、同一健康检查）。**唯一差异是库名** `go_user_system_test`——`assertTestDatabase`
   要求库名含 `test`，照抄 e2e 的 `go_user_system` 会直接 `t.Fatalf`。
2. `Run Go tests` 步设 `TEST_DATABASE_DSN`，按 `pkg/database/db.go:47` 的形态：
   `user:pass@tcp(host:port)/db?charset=utf8mb4&parseTime=True&loc=Local`。
3. 测试命令改为 `go test ./... -v` 并 `tee` 日志，**显式 `set -o pipefail`**
   （GitHub Actions 的 bash 默认 `-e` 但**不带 pipefail**，`| tee` 会吞掉测试失败的退出码）。
4. 新增断言步：日志里**必须**有 `--- PASS: Test…Integration…`，且**不得**有
   `--- SKIP: Test…Integration…`。缺日志文件也失败（fail-closed）。
5. 注释改写 `ci.yml:118-121` 那段事实：现在**配了**；**当前只覆盖 MySQL 方言**，
   **不覆盖** PG 迁移的方言残留；PG 版 `testutil` 属 M4。MySQL 版本 pin 与 #26 同批处理。

## 4. 验收（可判定）

| 方向 | 判据 | 命令 / 观察点 |
| --- | --- | --- |
| 正向 | 集成测**真执行**（非 skip） | CI `go` job 的 `Assert the MySQL integration tests actually ran` 步输出 `集成测试实际通过 N 个`（N 应 = 5）；且日志无 `SKIP: …Integration` |
| 负向 ①（代码内、持久） | DSN 已配时**不得** skip | `TestOpenMySQLDoesNotSkipWhenDSNIsSet`：用 `skipRecorder` 包住 `testing.TB` 记录 `Skip/Skipf` 调用——真实的 `t.Skip` 只会让测试变 SKIP（**在 CI 里是绿的**），这条测试让它变成 FAIL |
| 负向 ②（判据自身） | 断言步不能是死代码 | 用合成日志跑断言步的同一段 grep 逻辑：含 `SKIP … Integration` → 必须非零退出；无任何 `PASS … Integration` → 必须非零退出 |
| 回归 | 不带 DSN 时本地照旧绿 | `go test ./...` |

无数据、无外部资源残留（service 随 job 销毁）。

### 7.2 负向 ①：DSN 已配时不得 skip（代码内、持久）

新增用例 `TestOpenMySQLDoesNotSkipWhenDSNIsSet`（`internal/testutil/mysql_test.go`）。
它用 `skipRecorder` 包住 `testing.TB` 记录 `Skip/Skipf/SkipNow`——真实的 `t.Skip` 只会让用例
变成 SKIP（**CI 里是绿的**），这条把它变成 FAIL。

**注入验证**（临时把 `mysql.go:90` 的 `if dsn == ""` 改成恒真，跑完立即还原）：

```
=== RUN   TestOpenMySQLDoesNotSkipWhenDSNIsSet
    mysql_test.go:202: TEST_DATABASE_DSN 已配置，OpenMySQL 却 skip 了：set TEST_DATABASE_DSN to run MySQL integration tests
--- FAIL: TestOpenMySQLDoesNotSkipWhenDSNIsSet (0.00s)
FAIL	go-user-system/internal/testutil	1.101s
EXIT=1
```

还原后：`--- PASS: TestOpenMySQLDoesNotSkipWhenDSNIsSet`。`git status` 确认 `mysql.go`
**无残留改动**。

**另一条同类证据**（DSN 配了但库连不上时必须 FAIL 而非 SKIP）：
`TEST_DATABASE_DSN=…tcp(127.0.0.1:1)…` 跑 `go test ./internal/dao/ -run Integration` →
`open test mysql failed: dial tcp 127.0.0.1:1 …`、`EXIT=1`，无 SKIP。

### 7.3 负向 ②：断言步不是死代码

把 `ci.yml` 里那一步的 shell **原样抽出**，在 Git Bash 下喂四种合成日志：

| 用例 | 合成日志 | 结果 | 期望 |
| --- | --- | --- | --- |
| A | 5 条 `--- PASS: Test…Integration` | `集成测试实际通过 5 个，被跳过 0 个`，exit **0** | ✅ |
| B | 2 条 `--- SKIP: Test…Integration` | `被跳过 2 个` + 列出 SKIP，exit **1** | ✅ |
| C | 只有单元测试 PASS | `没有任何集成测试被执行 —— 这道门当前是空的`，exit **1** | ✅ |
| D | 日志文件不存在 | `找不到 …`，exit **1** | ✅ |

> 这一步在本机也真实咬到了「BOM 吃掉第一行」：PowerShell 5.1 的 `Set-Content -Encoding utf8`
> 给脚本加了 BOM，bash 报 `$'\357\273\277set': command not found`、**退出码却是 0**。
> 改用无 BOM 写入才得到上表。**CI 里没有这一步**（YAML 里的 `run:` 不经 PowerShell），
> 但它说明「退出码 0」仍可能来自一个没跑起来的脚本——断言步的 fail-closed 分支正是为此。
