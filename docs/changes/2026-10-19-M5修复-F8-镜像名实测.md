# 2026-10-19 · M5 修复 F8 · 镜像名读实测 / 预检与演练读同一组变量

> 依据：M5 三跳链阻断项 **F8**（A11 + A12）。

## A11 · `monthly-ops.sh` 的镜像预检读字面量

原代码（HEAD `:355`）：

```bash
for image in "postgres:18-alpine" "redis:7.4-alpine"; do
    docker image inspect "$image" >/dev/null 2>&1 || missing_images=…
```

两处问题：① 漏了**认证库镜像**；② **无视 ops.conf / 环境变量里的覆盖**，
而真正执行演练的 `verify-restore.sh` 读的是 `POSTGRES_IMAGE` / `AUTH_POSTGRES_IMAGE` /
`REDIS_IMAGE`。预检与演练不是同一组输入 ⇒ 这条提示**不携带信息**：
它报「都在」时演练可能找不到镜像，它报「缺」时演练可能跑得起来。

**改动**：改成 `ops_conf_get POSTGRES_IMAGE|AUTH_POSTGRES_IMAGE|REDIS_IMAGE`
（与 `verify-restore.sh` 同名的三个变量、同样的默认值），并在报告里对重复镜像去重
（主库与认证库通常同镜像，否则同一名字会列两遍）。

## A12 · metadata 里的镜像名写死

`backup-all.sh` 原写 `postgres_image=postgres:18-alpine` / `redis_image=redis:7.4-alpine`
（`auth_postgres_image` 用的是可配置变量，但仍是**配置值**，不是事实）。

**改动**：新增 `inspect_image()`，对每个服务做
`docker inspect --format '{{.Config.Image}}' "$(compose ps -q <service>)"`，
metadata 写**实测值**。这样镜像升级后 metadata 与事实不再脱节。

## 边界

- 本机无 Docker：`docker inspect` / `docker image inspect` 用桩（按容器 ID 后缀映射镜像名、
  按白名单判断镜像是否存在）；`jq` 用一个「输出空、exit 0」的桩（只影响汇总报告格式化）。
- **`docker inspect` 的真实输出格式未在本机验证**；`{{.Config.Image}}` 的取值在真实 compose
  容器上应等于 compose 文件里的 `image:`（含 registry 前缀与 tag），这一点以真机为准。
- `monthly-ops.sh` 其余章节（apt / lynis / 记录扫描）在替身环境下不具代表性，未作为判据。
