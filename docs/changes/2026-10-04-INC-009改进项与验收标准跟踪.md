## 2. 7 条永久修复验收标准对账

来源：`INC-009`「永久修复验收标准」。**这些是行为级判据，多数需要浏览器或生产实测**，
所以这里的判定严格按「有没有留痕的证据」——没有证据的一律记「未验收」，**不按推断算过**。

| # | 验收标准 | 判定 | 说明 |
|---|---|---|---|
| 1 | 改密后旧会话访问受保护页跳登录页，不出现数据库故障提示 | **未验收** | 代码路径已具备（改动 1+2），但无「改密 → 旧页面导航」的实测留痕 |
| 2 | 页面开超 15 分钟后 Refresh 仍有效时可自动续期并保存 | **部分验收** | 生产 HTTP 层构造「access 失效 + refresh 有效 → 200 并下发新 cookie」✅；**浏览器 UI 层未验**（§4.5.3 自评） |
| 3 | Refresh 也失效时明确提示重新登录、不进入数据库错误页、尽量保留未保存内容 | **部分验收** | 「提示重登 + 无『数据库』字样」有测试 ✅；**「保留未保存内容」无验证** |
| 4 | 用新密码登录后首页/知识库/采集页正常加载 | **未验收** | — |
| 5 | PostgreSQL 与认证服务健康检查持续正常 | **已验收** | 巡检与 `/api/health/*` 长期在跑，最近一次 daily-ops `FAIL=0`【依据：巡检报告】 |
| 6 | 日志能通过请求 ID 定位异常类型，不泄露密码/Cookie/令牌/IP | **部分验收** | `requestId` 已在 API 层统一（改进 5）；**「不泄露」无针对性验证** |
| 7 | 普通认证失效不触发数据库故障告警 | **未验收** | 无「认证失效 → 确认无 DB 告警」的对照实验留痕 |

**小结：7 条中 1 条已验收、3 条部分、3 条未验收。** 这部分**不是代码缺口，是验收留痕缺口**——
它属于十环的第 03 环（测试门禁）与第 07 环（排障回写）的交界，要靠**真实环境跑一次并归档**
才能关闭，不能靠读代码判定。
